가이드 편도 여유가 **15mm** 인데 300mm 벗어나니, 코드가 `phase="lane"` 로

### 틀린 진단 2개 (남겨 둔다)

1. **"배경 씬에서 어셈블리가 옮겨졌다"** → 틀렸다. 옛 씬에서도 같은 숫자다.
2. **"config `radius_mm` 1910 이 실제 기하와 다르다"** → 틀렸다.
   실측 `|home[0] − cx|` 가 이미 1.91 이었다 ("호 반지름을 씬에서 잰다" 로그가
   안 찍혔다). 수정은 남겼지만 **no-op** 이다.

### 남은 의심

두 값을 **다른 기준으로 재고 있다**:
```python
train["lane_y"] = _bbox(...)                 # ComputeWorldBound → 월드 · 기하 중심
pal_t[1]        = _translate_op(pal).Get()   # 프림의 로컬 translate → 원점
```

**다음 단계는 추측이 아니라 진단 로그다** — 진입 x, 진입/출구의 실제 반지름,
누적 회전각, `bbox 중심 − translate` 차이. (`demo/bg-scene` 브랜치에 이미 있다)

**현재 대응** — 반출은 세 번 다 `트럭 적재 완료` 로 성공한다. **화면에만 보이는
문제**라 발표 영상에서 그 구간을 빠르게 넘긴다.

## 12. 노드를 두 군데서 띄우면 조용히 어긋난다

ROS 2 는 **같은 이름의 서버·발행자가 둘이어도 에러를 안 낸다.**

| | 규칙 |
|---|---|
| 서비스 서버 (`db`·`algo`) | **정확히 1개** |
| 명령 발행자 (관제탑 → `/robot/cmd`) | **정확히 1개** |
| 좌표 발행자 (`/zone_*/box_at_pickup`) | **정확히 1개** ← 2번 사고가 이 계열 |
| 구독자 (`live_view`·rqt·웹) | 몇 개든 OK |

**DB 를 양쪽에서 켜면** 인식은 A 에 등록하는데 관제탑은 B 에 물어본다 →
"박스 정보 없음" 으로 버려진다. **에러는 안 뜬다.**

### 어디에 무엇을 두나

| 노드 | 옮길 수 있나 | 왜 |
|---|---|---|
| Isaac Sim | ❌ 고정 | GPU + 씬 USD |
| vision | ⚠ 사실상 고정 | 이미지가 커서 UDP 단편 손실 (§15) |
| db | ✅ | 단 `.db` 파일이 그 PC 에 |
| algo · 관제탑 · live_view | ✅ | 메시지가 작다 |

> ⚠ `.db` 는 예외가 하나 더 있다 — Isaac 이 [sim_main.py:758](../src/packing_sim/isaac/sim_main.py#L758)
> 에서 `boxes_master` 를 로컬 파일로 직접 읽는다 (Isaac 안이라 rclpy 를 못 써서
> 만든 임시 경로). **파일은 양쪽에, 서비스 노드는 한쪽에만.**

### 어떻게 나누든 4가지는 모든 PC 에서 같아야 한다

1. `ROS_DOMAIN_ID=115`
2. `use_sim_time:=true` + `/clock` 발행자 존재 → **Isaac 을 항상 먼저**
3. `PL_CONFIG_OVERLAY` — 안 주면 관제탑·algo 가 test1-1 좌표로 계획한다
4. 같은 브랜치로 빌드 — `packing_msgs` 타입 해시가 다르면 연결 자체가 안 된다

**넷 다 안 맞으면 에러 없이 틀린다.**

> `orchestrator:=false` 를 주면 10초 경고가 뜬다 — **2-PC 면 정상이다.**
> `PL_NET=local` 은 **주지 않는다** (기본 subnet 이라야 PC2 가 본다).

**PC2 — 터미널 1 (관제탑 + DB)**
```bash
cd ~/palletris_ws && source install/setup.bash \
  && export ROS_DOMAIN_ID=115 RMW_IMPLEMENTATION=rmw_fastrtps_cpp \
            ROS_AUTOMATIC_DISCOVERY_RANGE=SUBNET \

            PL_CONFIG_OVERLAY=src/packing_bringup/config/test_3.yaml \
  && ros2 launch packing_bringup bringup.launch.py vision:=false algo:=false db:=true
```

**PC2 — 터미널 2 (대시보드, 첫 박스 집히기 전에)**
```bash
ros2 run packing_algo live_view --ros-args -p use_sim_time:=true
```

**순서** — ① PC1 이 `[2/2] bringup` 을 찍을 때까지 대기 → ② PC2 관제탑 → ③ 대시보드.
②를 먼저 하면 `/clock` 이 없어 타이머가 전부 멎는다 (**에러 없이**).

### 자주 쓰는 환경변수

| 변수 | 기본 | 뜻 |
|---|---|---|
| `PL_RENDER_EVERY` | 3 | N프레임에 1번 렌더. 클수록 빠르고 화면이 끊긴다 |
| `PL_SPAWN` | — | 박스 투입 간격(초) |

| `PL_NET` | subnet | `local` 이면 이 PC 안에서만 |
| `PL_OUTFEED` | 1 | 만재 팔레트 반출 연출 |

## 14. 이날 얻은 규칙

1. **"아까 됐던 실행"을 기준으로 삼기 전에 그 판이 진짜 됐는지 로그로 확인한다.**
   화면이 도는 것과 파이프라인이 다 살아 있는 것은 다르다 (10:47 사고).
2. **한 번에 하나씩만 바꾼다.** 이날 실패의 절반은 여러 변경이 겹쳐서
   무엇이 원인인지 못 가린 것이다.
3. **추측으로 두 번 고쳐서 실패하면 세 번째는 진단 로그부터 넣는다** (§11).
4. **ROS 2 는 틀려도 소리를 안 낸다.** 토픽 이름·도메인·QoS·타입 해시가 안 맞으면
   에러가 아니라 **침묵**이다. "안 온다" 는 증상은 항상 이 목록부터 본다.
5. **CLAUDE.md §15 의 경고를 기본값으로 뒤집지 않는다** (`prefer` 사고).
6. **계획 파라미터는 Isaac 으로 판정한다** (§10-1). 데스크 지표와 부호까지 어긋난다.
