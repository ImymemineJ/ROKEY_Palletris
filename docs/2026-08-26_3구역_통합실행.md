## 0. 먼저 끝나야 하는 것 (A · B)

| | 누가 | 없으면 |
|---|---|---|
| `setup_test3_scene.py` 실행 | A (씬) | `/clock`·`/tf` 가 없다 → **모든 타이머가 멎는다** |
| 카메라 ROS 발행 | B (카메라) | `/zone_*/box_at_pickup` 이 안 온다 → 관제탑이 IDLE 로 대기 |

⚠ **씬에 ROS2 노드가 0 개다** (2026-08-26 실측 — 그래프 43 개가 전부 컨베이어).
`ros2 topic info /tf` 가 Publisher 0 이다. A 가 끝나야 그게 생긴다.

카메라 계약 (B 와 맞춘 것):
- 토픽 `/pick_cam_a/rgb` + `/pick_cam_a/camera_info` (b · c 도 같은 꼴)
- `ROS2CameraHelper` 의 **`frameId` 는 씬 prim 이름** — `CamPick_A`.
  `ROS2PublishTransformTree` 가 프레임 이름을 prim 이름으로 정하고,
  `vision_node` 는 **이미지 헤더의 `frame_id` 로 tf 를 조회**한다. 둘이 같아야 한다.
- ⚠ `cam1`(등록)·`cam2`(검증)에 해당하는 투입부 카메라가 씬에 `CamSpawn` 하나뿐이다.
  하나로 갈지 하나 더 놓을지 미정.

## 2. 터미널 2 — ROS 그래프 전체

```bash
cd ~/palletris_ws && source /opt/ros/jazzy/setup.bash && source install/setup.bash && \
export ROS_DOMAIN_ID=115 && \
ros2 launch packing_bringup bringup.launch.py \
  zones:="['a','b','c']" \
  pick_cam_ns:="['/pick_cam_a','/pick_cam_b','/pick_cam_c']" \
  config_overlay:=$PWD/src/packing_bringup/config/test_3.yaml
```

★ `config_overlay` 를 **반드시** 준다. 안 주면 관제탑·algo 가 test1-1 좌표로
계획하고 Isaac 은 test_3 좌표로 움직인다 — **경고 없이** 어긋난다.

★ Isaac 을 **먼저** 띄운다. launch 가 `use_sim_time:=true` 를 강제하는데
`/clock` 발행자가 없으면 ROS 시계가 0 에 멎어 **관제탑의 20 초 로봇 타임아웃
감시까지 죽는다** (노드는 살아 있고 에러도 없다).

DB 가 비어 있으면 한 번:

```bash
cd ~/palletris_ws && source install/setup.bash && ros2 run packing_db gen_master_db
```

## 4. 인식이 아직이면 — 손으로 박스 도착을 쏜다

카메라가 준비 안 됐어도 상태머신은 끝까지 돈다.

```bash
ros2 service call /db/register_box packing_msgs/srv/RegisterBox "{box_id: 'BOX001', size_w_mm: 340, size_d_mm: 250, size_h_mm: 210, color: 'red', dest: '', qr_payload: ''}"
```

```bash
ros2 topic pub --once /zone_b/box_at_pickup packing_msgs/msg/BoxAtPickup "{box_id: 'BOX001', present: true, x_mm: 9800, y_mm: 0, yaw_deg: 0.0}"
```

⚠ `box_id` 는 **`BOX001` 형식(3 자리)** 이다. 마스터 DB 가 그 형식이라
`BOX00001` 은 "master 에 없는 박스" 로 거절된다.
⚠ `x_mm`·`y_mm` 는 **test_3 좌표**여야 한다 (위 예시는 test1-1 값이다).

관제탑에서 이 순서가 보이면 성공이다:

```
[①→②] 박스 도착 → [②→③] 크기 → [③→④] 놓을 자리
[④→⑤] 집기 성공 → [⑤→⑥] 놓기 성공 → [⑥→①] 적재 n개
```

## 5. 막혔을 때 — 증상별

| 증상 | 먼저 볼 것 |
|---|---|
| 관제탑이 `IDLE` 에서 안 움직인다 | `/zone_*/box_at_pickup` 발행자가 있나 (카메라·B) |
| `FETCHING` 에서 되돌아온다 | `/conveyor/set_velocity` 서버가 있나 (Isaac `--ros`) |
| `DB에 없음 → 폐기` | `gen_master_db` 실행 · `box_id` 형식(3 자리) |
| `로봇 응답 없음 — 20.3초` | Isaac 로그에 `[adapter] ←` 가 찍혔나. 안 찍혔으면 토픽 구역이 어긋난 것 |
| 타이머가 하나도 안 돈다 | `/clock` 발행자 0 (Isaac 을 먼저 띄웠나 · 씬에 ROS 노드가 있나) |
| 팔이 엉뚱한 데로 간다 | **오버레이가 안 걸렸다** — 1 번의 베이스 경고 확인 |
| 씬은 열리는데 로봇이 없다 | USD 절대경로 — `scripts/fix_usd_abs_paths.py` |

## 6. 알려진 것 (안 고쳐도 도는 것)

- **`RobotEvent` 중복 발행** — PICK 1 건에 약 2000 건이 나간다.
  관제탑이 `seq` 로 거르므로 동작에는 지장이 없다. 원인 미상 (`ros_graph.py` 참조).
- **`SetVelocity.actual_mps` 가 항상 0.0** — Isaac ROS2 브리지가 서비스 응답의
  float 을 못 쓴다 (TS-023). 관제탑은 `ok` 만 보므로 지장 없다.
