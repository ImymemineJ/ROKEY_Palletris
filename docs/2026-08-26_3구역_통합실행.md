## 0. 먼저 끝나야 하는 것 (A · B)

| | 누가 | 없으면 |
|---|---|---|
| `setup_test3_scene.py` 실행 | A (씬) | `/clock`·`/tf` 가 없다 → **모든 타이머가 멎는다** |
| 카메라 ROS 발행 | B (카메라) | `/zone_*/box_at_pickup` 이 안 온다 → 관제탑이 IDLE 로 대기 |

⚠ **씬에 ROS2 노드가 0 개다** (2026-08-26 실측 — 그래프 43 개가 전부 컨베이어).
`ros2 topic info /tf` 가 Publisher 0 이었다.

★ **그래서 런타임에서 메운다** (2026-08-26). `ros_graph.build_clock_tf()` 가
`/clock`·`/tf` 를 **씬에 없을 때만** 세운다. A 가 씬을 고치면 이 함수는 저절로
비켜선다 (`ROS2PublishClock` 노드를 찾으면 안 만든다) — 지울 필요가 없다.
`/clock` 발행자가 둘이면 tf 조회가 "extrapolation into the future" 로 실패하므로
이 검사는 없으면 안 된다.

⚠⚠ `ROS2PublishClock` 에 **시간 소스를 안 물리면 `/clock` 이 계속 0 을 낸다.**
`IsaacReadSimulationTime.outputs:simulationTime` -> `Clock.inputs:timeStamp` 가
있어야 한다. 없어도 토픽은 멀쩡히 보이고 발행자 수도 1 이라 **됐다고 착각하기
딱 좋은데**, 구독 노드들의 시계가 0 에 멎어 타이머가 하나도 안 뜬다 — `/clock` 이
아예 없을 때와 증상이 똑같다. `setup_test3_scene.py [11]` 에도 같은 결함이
있어서 같이 고쳤다.

카메라 계약 (B 와 맞춘 것):
- 토픽 `/pick_cam_a/rgb` + `/pick_cam_a/camera_info` (b · c 도 같은 꼴)
- `ROS2CameraHelper` 의 **`frameId` 는 씬 prim 이름** — `CamPick_A`.
  `ROS2PublishTransformTree` 가 프레임 이름을 prim 이름으로 정하고,
  `vision_node` 는 **이미지 헤더의 `frame_id` 로 tf 를 조회**한다. 둘이 같아야 한다.
- ⚠ `cam1`(등록)·`cam2`(검증)에 해당하는 투입부 카메라가 씬에 `CamSpawn` 하나뿐이다.
  하나로 갈지 하나 더 놓을지 미정.

| 그 `.so` 와 **다른 ROS 배포판** (Isaac 내장 vs 시스템) | `symbol lookup error: … undefined symbol: _ZN8eprosima7fastcdr3Cdr9serializeEPc` — fastcdr ABI 가 다르다 |

★ **Isaac 내장 ROS 2 를 쓰면 안 된다.** `packing_msgs` 는 `/opt/ros/jazzy` 로
빌드돼 있다. `source install/setup.bash` 한 줄이 셋을 한꺼번에 해결한다.

## 4. 인식이 아직이면 — 손으로 박스 도착을 쏜다

카메라가 준비 안 됐어도 상태머신은 끝까지 돈다.

```bash
ros2 service call /db/register_box packing_msgs/srv/RegisterBox "{box_id: 'BOX001', size_w_mm: 340, size_d_mm: 250, size_h_mm: 210, color: 'red', dest: '', qr_payload: ''}"
```

```bash
ros2 topic pub --once /zone_b/box_at_pickup packing_msgs/msg/BoxAtPickup "{box_id: 'BOX001', present: true, x_mm: 9800, y_mm: 0, yaw_deg: 0.0}"
```

⚠ `box_id` 는 **`BOX001` 형식(3 자리)** 이다. 마스터 DB 가 그 형식이라
`BOX00001` 은 "master 에 없는 박스" 로 거절된다.
⚠ `x_mm`·`y_mm` 는 **test_3 좌표**여야 한다 (위 예시는 test1-1 값이다).

관제탑에서 이 순서가 보이면 성공이다:

```
[①→②] 박스 도착 → [②→③] 크기 → [③→④] 놓을 자리
[④→⑤] 집기 성공 → [⑤→⑥] 놓기 성공 → [⑥→①] 적재 n개
```
