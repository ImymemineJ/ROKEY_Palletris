## 2. ★ 소켓과 함께 죽으면 안 되는 것 3개

폐기 파일에 있던 것 중 **실측으로 산 지식**이다. 새 로봇 노드가 이어받아야 한다.

### (1) Cycle 을 명령마다 새로 만들지 마라

```python
# 폐기된 orchestrator.py:ensure_link() 주석
# ★ Cycle 을 새로 만들지 않는다. _stack_top_m(누적 적재 최상단, 42690a9)이
#   0 으로 돌아가면 재연결 뒤 첫 이송이 적재물 높이를 잊고 기둥을 지나간다.
```

`Cycle` 은 **상태를 들고 있다.** `_stack_top_m` 은 지금까지 쌓은 것 중 가장 높은 값을
누적한 것이고, 이송 고도가 여기서 나온다 (42690a9). 새 로봇 노드가
`RobotCmd(PICK)` 마다 `Cycle()` 을 생성하면 그 값이 0 으로 리셋되고,
**팔이 적재물 위를 낮게 지나가며 스택을 친다** — CLAUDE.md §10-3 이 기록한
knock 700.8 mm 사고와 같은 경로다. 로봇 노드는 구역당 `Cycle` 을 **하나만** 만들어
계속 재사용한다.

### (2) ~~메인 벨트를 켜는 주체가 사라졌다~~ **오해였다 (2026-08-26 정정)**

폐기 파일에 이런 주석이 있었다:

```python
# ★ 메인 벨트는 켜 두고 계속 돌린다. 박스는 x=500(메인 구간 0~7500)에 스폰되므로
#   이걸 안 켜면 스폰만 되고 영영 안 움직인다.
```

이걸 보고 "관제탑이 `main` 을 안 켜니 통합하면 박스가 안 온다"고 적었는데 **틀렸다.**
씬 쪽을 안 열어 본 채 단정했다 (김학민 지적).

```python
# sim_main.py:200
cc.run_all() if a.autorun else cc.stop_all()
```

`--autorun` 이면 `ConveyorCtl.run_all()` 이 **모든 seg 를 사양 속도로 돌리고
소터 방향까지 세팅한다.** 관제탑은 `b_pickup` 만 멈췄다 켰다 하고 `main` 은
건드리지 않으므로 그대로 굴러간다. 관제탑에도 씬에도 아무것도 넣을 필요가 없다.

내 옛 orchestrator 가 `main` 을 명시적으로 켠 것은 **`--autorun` 없이** 띄우는 걸
전제했기 때문이다 (그 경우 `stop_all()` 로 시작해 "정지 — set_velocity 대기").

⚠ 다만 **둘 다 침묵으로 실패한다.** 박스가 스폰되고 관제탑은 IDLE 로 영원히
기다리는데 에러는 안 뜬다:

| 빠뜨리면 | 증상 |
|---|---|
| `--autorun` | `stop_all()` 로 시작 → 박스가 안 움직인다 |
| `--no-render` 를 켜면 | `sim_main.py:85` **"★ 벨트가 안 돈다"** |

### (3) 워커가 죽었는데 `IDLE` 을 광고하는 문제

```python
# 폐기된 orchestrator.py:sim() 주석
# 거기서 예외가 나면 워커 스레드만 죽고 rclpy.spin 은 메인 스레드에서 계속 돌아,
# 노드가 **죽었는데 state=IDLE 을 계속 광고한다.** 중재자가 그 값으로 배정을
# 정하므로 크래시보다 나쁘다 — 상대가 알아차릴 방법이 없다.
```

범진 관제탑은 콜백 구동이라 워커 스레드가 없다 — 이 경로는 사라졌다. 하지만
**새 로봇 노드에는 워커 스레드가 다시 생긴다** (`Cycle.run()` 이 블로킹이다).
로봇 노드가 죽으면 `RobotEvent` 가 영영 안 오고, 관제탑은 `check_robot_timeout`
(20초) 으로만 알아차린다. 로봇 노드는 워커 예외를 잡아 **반드시 `RobotEvent(ok=false,
reason="ABORTED")` 를 seq 와 함께 돌려보내야** 한다.

## 3. 새 로봇 노드가 메울 간극

관제탑은 **사이클 단위**로 말하고, `Cycle` 은 **동작 단위**로 말한다. 1:1 대응이 없다.

| `RobotCmd.action` | `Cycle` 내부 호출 |
|---|---|
| `PICK` | `move_ee`(접근) → `move_ee`(하강) → `grasp` → `move_ee`(상승) |
| `PLACE` | `move_ee`(이송) → `move_ee`/낙하 → `release` → `move_ee`(안전고도) |
| `HOME` | `move_ee`(홈) |
| `STOP` | 진행 중 모션 중단 |

응답 규약 (CLAUDE.md §3-4):
- `RobotEvent.seq` 는 `RobotCmd.seq` 를 **그대로 복사**한다
- `PLACE` 성공 시에만 `has_actual=true` + `actual_*`. **계획값을 되보내지 않는다**
- 실패 사유는 `GRASP_FAILED`|`IK_UNSOLVABLE`|`COLLISION`|`DROPPED`|`TIMEOUT`|`ABORTED`
