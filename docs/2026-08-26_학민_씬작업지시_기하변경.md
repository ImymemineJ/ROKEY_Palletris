`test_3` 의 로봇·팔레트 기하를 **test1-1 에서 실측 검증된 관계**로 맞춥니다.

| | 지금 | → 바꿀 값 |
|---|---|---|
| 페데스탈 높이 | 1950 | **1700** |
| 팔레트 X 이격 | 400 | **500** (팔레트를 −X 로 100) |
| `max_stack` | 1000 | **1300** |

**로봇의 X·Y 는 건드리지 않습니다.** 옮기는 것은 팔레트와 페데스탈 높이뿐입니다.

## 1. 왜 — 규칙보다 실측

`test_3.yaml` 은 `max_stack = 페데스탈 − 팔레트상면` 이라는 **스윕 규칙**으로
기하를 정했습니다 (1950 − 950 = 1000).

그 규칙은 **test1-1 에서 이미 깨졌습니다:**

```
test1-1  페데스탈 900 · 팔레트상면 150  →  규칙상 750
         실제로 세운 것  1300 (9단 · 적재율 80.3%)   results/relief_s42.txt
```

협곡 낙하(`heightmap.drop_relief_mm`)가 뚫었습니다. 팔이 협곡으로 안 내려가도
되니 `_corridor_ok` 의 전제가 사라집니다. CLAUDE.md §10-1 — **계획 파라미터는
Isaac 으로 판정한다.**

### 두 씬은 이미 같은 배치입니다

|  | 이격축 팔레트폭 | 측면(로봇 중앙에서) |
|---|---|---|
| test1-1 | 800 | 600 |
| test_3 | 800 | 600 |

**다른 것은 팔레트 높이 하나**입니다 — 바닥 150 vs 셀 컨베이어 950.
로봇도 그만큼 내리면 같은 조건이 됩니다:

```
베이스 − 팔레트상면(dz)    test1-1   900 − 150 =  750
                           test_3   1700 − 950 =  750    ← 페데스탈 1950 → 1700
```

### 도달거리로 검산 (H2017 = 1700 mm)

| 조건 | 빈 팔레트 최원점 | |
|---|---|---|
| test1-1 이격 500 · dz 750 | **1616.3** | 여유 83.7 — 어제 9단 조건 |
| **test_3 이격 500 · dz 750** | **1616.3** | **완전히 동일** |
| test_3 이격 400 · dz 1000 | 1673.3 | 여유 26.7 (현재) |
| test_3 이격 500 · dz 1000 | 1746.4 | **초과** — 페데스탈 1950 이 문제 |

> 검산 검증: 현재값(이격 400·dz 1000)으로 넣으면 **1673.3** 이 나오는데,
> `test_3.yaml` 주석의 "빈 팔레트 최원점 1673.3" 과 소수점까지 같습니다.

트럭도 확인했습니다 — 팔레트 150 + 적재 1300 = **1450 < 내고 1600** ✅

## 2. ★★ 절대 하지 말 것

### ① 로봇을 옮기지 마세요

**지선(픽업 라인)이 로봇 X 에 정렬돼 있습니다.**
`setup_test3_scene.py` 검증 출력 그대로:

```
지선 중심 = 로봇 X       OK -19596.0 vs -19596.0
```

로봇을 X 로 옮기면 픽업이 어긋납니다. **이격은 팔레트를 −X 로 옮겨서** 벌립니다.

### ② Y 를 넓히지 마세요

`test_3` 는 축 역할이 `test1-1` 과 다릅니다:

```
test_3 의 X  =  팔레트 이격   (test1-1 의 Y 역할)   ← 여기만 400 → 500
test_3 의 Y  =  픽업 방향     (로봇 5076 ~ 스토퍼 4181 = 895)   ← 그대로
```

Y 를 넓히면 팔이 가이드 쪽으로 밀립니다.

### ③ 기둥(Pedestal)을 빼놓지 마세요

`Pedestal_A/B/C` 는 **원통이고 중심이 절반 높이**에 있습니다.
로봇만 내리면 로봇이 기둥 위에서 벗어나 허공에 섭니다.
**중심 z 와 scale.z 를 같이** 바꿔야 합니다.


**먼저 `--dry-run` 을 붙여 계산만 보는 것을 권합니다.** 도달거리를 넘으면

## 4. 방법 B — GUI 로 직접 (스크립트를 안 쓸 경우)

### 씬 (`test_3.usd`)

| 프림 | 속성 | 지금 | → |
|---|---|---|---|
| `/World/robot_A` | translate.z | 1.950 | **1.700** |
| `/World/robot_B` | translate.z | 1.950 | **1.700** |
| `/World/robot_C` | translate.z | 1.950 | **1.700** |
| `/World/Pedestal_A` | translate.z | 0.975 | **0.850** |
| `/World/Pedestal_A` | scale.z | 1.625 | **1.41667** |
| `/World/Pedestal_B` | translate.z / scale.z | 0.975 / 1.625 | **0.850 / 1.41667** |
| `/World/Pedestal_C` | translate.z / scale.z | 0.975 / 1.625 | **0.850 / 1.41667** |
| `/World/Pallet_A` | translate.x | −8.396 | **−8.496** |
| `/World/Pallet_B` | translate.x | −14.396 | **−14.496** |
| `/World/Pallet_C` | translate.x | −20.396 | **−20.496** |

> 기둥 원통의 `height` 속성은 **1.2 로 그대로** 둡니다.
> 실제 높이 = `height × scale.z` = 1.2 × 1.41667 = **1.7 m**.
> `Pallet_*` 의 y·z 는 그대로입니다 (팔레트 상면 950 유지).

### 설정 (`src/packing_bringup/config/test_3.yaml`)

```yaml
robot:
  pedestal_height_mm: 1700          # 1950 에서

pallet:
  max_stack_mm: 1300                # 1000 에서

zones:
  pallet_origin_world_mm:
    A: [-8896, 4476, 950]           # x 만 -100  (-8796 -> -8896)
    B: [-14896, 4476, 950]
    C: [-20896, 4476, 950]

  robot_base_world_mm:
    A: [-7596, 5076, 1700]          # z 만 1950 -> 1700. x·y 그대로
    B: [-13596, 5076, 1700]
    C: [-19596, 5076, 1700]
```

⚠ `pallet_origin_world_mm` 과 `robot_base_world_mm` 은 **줄 모양이 똑같습니다**
(`A: [숫자, 숫자, 숫자]`). 파일 전체 찾아바꾸기를 하면 엉뚱한 쪽을 덮어씁니다 —
블록을 보고 고쳐 주세요. (제 스크립트도 그 함정에 한 번 빠졌습니다.)

## 5. ★ 순서 — 가이드 벽을 반드시 다시 세워야 합니다

**팔레트를 옮겼으므로 가이드 벽이 어긋납니다.** `setup_test3_scene.py` 의
`[10] 팔레트 가이드 벽` · `[12] 적재 스테이션 가이드 벽` 이 팔레트 기준으로
세우므로, 기하 변경 **뒤에** 한 번 더 돌려 주세요.

```bash
PL_STAGE=$HOME/isaac_scenes/project_1/test_3.usd \
PL_CONFIG_OVERLAY=$HOME/palletris_ws/src/packing_bringup/config/test_3.yaml \
LD_LIBRARY_PATH=$LD_LIBRARY_PATH:$HOME/isaac-sim-5.1.0/exts/isaacsim.ros2.bridge/jazzy/lib \
~/isaac-sim-5.1.0/isaac-sim.sh --no-window \
    --exec $HOME/palletris_ws/scripts/setup_test3_scene.py
```

★ `LD_LIBRARY_PATH` 를 같이 붙였습니다 — 그래야 **`[11] ROS 2 브리지`가 성공**합니다.
  지난 실행에서 `RESULT: 실패 — ROS2 브리지 노드 생성` 이 났는데, 스크립트가
  안내하는 그 경로입니다. 확장 폴더는 실제로 있는 것을 확인했습니다.
  그게 붙어야 `/clock` · `/tf` 가 나옵니다 (지금 씬의 **ROS2 노드는 0개**,
  OmniGraph 43개가 전부 컨베이어).

★ 경로 기본값이 `/home/rokey/...` 라 **환경변수 두 개를 꼭** 주셔야 합니다.

## 7. 별건 두 개 — 같이 봐 주시면 좋겠습니다

### ① 스토퍼가 test1-1 보다 3배 높습니다

| | 스토퍼 상면 | 벨트(800) 위로 |
|---|---|---|
| test1-1 `/World/Stopper` | 900 | +100 |
| **test_3 `/World/Stopper_A/B/C`** | **1100** | **+300** |

`Stopper_B` = 중심 z 0.95 · 높이 0.3 → **z 0.80 ~ 1.10**

| 박스 | 상면 | 스토퍼(1100) 대비 |
|---|---|---|
| 3호 | 1010 | **−90** ❌ |
| 4호 | 1080 | **−20** ❌ |
| 5호 | 1140 | +40 ⚠ |

**3호·4호는 박스 윗면이 스토퍼보다 낮아 흡착 패드가 스토퍼에 올라탑니다.**

실측 (관제탑 → Isaac 전 구간, zone B, 3호):

```
[robot_motion] 도착 잔차 87.90 mm (허용 2.0)
               흡착면 z 1.0999  →  목표 1.012
```

멈춘 z 1.0999 가 **스토퍼 상면 1.100 과 0.1 mm 차이**입니다.
페데스탈을 120 mm 내려도 **같은 값**이 나온 것이 결정적 근거였습니다
(도달 한계라면 같이 내려갔어야 합니다).

→ **`Stopper_A/B/C` 의 높이를 300 → 100 으로** (test1-1 과 같게) 부탁드립니다.
  박스 혼입비가 3호 0.5 · 4호 0.3 이라, 이대로면 **80% 가 픽업에서 실패**합니다.

### ② 소터가 한 번도 안 켜집니다 (씬 아니라 드라이버)

`demo_stack15_test1_1.py` 가 소터에 **방향만** 줍니다:

```python
kw = {"cmd": "set_sorter", "zone": zone, "divert": bool(want_div)}   # mps 없음
```

`conveyor_ctl.h_set_sorter` 규약은 *"`mps` 를 주면 속도도 바꾼다 —
**안 주면 건드리지 않는다**"* 이고 A47 애셋의 `SorterSpeed` 기본값은 **0.0** 입니다.
`belt_graphs` 16 세그먼트에도 소터가 없어 `set_velocity` 로도 안 켜집니다.

실측 (`Videos/260826`, `PL_ZONES=A,B,C`):

```
대기 30 s  000(-6.12) 001(-4.77) 002(-3.15) 003(-1.54)   ← 4.6 m 에 흩어짐
대기 45 s  000(-7.03) 001(-6.66) 002(-6.05) 003(-4.61)
대기 60 s  000(-7.57) 001(-7.20) 002(-6.79) 003(-6.34)   ← 1.6 m 로 뭉침
```

느려진 게 아니라 **존 A 분기(−8048~−7144)에서 막혀 뒤가 밀린** 것입니다.
(간격이 좁아지는 것이 근거입니다 — 느린 것과 밀리는 것은 좌표 분포로 갈립니다.)

`sim_main --autorun` 은 `cc.run_all()` 이 소터까지 켜므로 이 문제가 없습니다.
