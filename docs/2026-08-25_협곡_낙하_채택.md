# 협곡 문제 — 낙하로 푼다 (트랙 B)

**2026-08-25 저녁 · 김병직**

## 요약 네 줄

1. 팔이 협곡에 못 들어가는 문제를 **계획을 조여서** 풀려던 시도는 전부 적재율을 깎았다.
2. 대신 **협곡 입구에서 놓아 떨어뜨린다.** 팔이 안 내려가므로 걸릴 일이 없다.
3. ★ 그러면 **계획도 그만큼 풀어야 한다** — `_corridor_ok` 는 "팔이 따라 내려간다" 를
   전제로 만든 규칙이라, 떨어뜨릴 수 있는 박스에는 과하다. 이게 제일 큰 레버였다.
4. 시드 42/7/99 **3/3 통과 · 적재율 75.5% · 셋 다 `PALLET_FULL` 로 종료.**

## ★ 최종 (2026-08-25 밤)

```bash
PL_CONTACT_STOP=1 PL_DROP_KG=3.5 \
~/isaac-sim-5.1.0/python.sh scripts/demo_stack15.py \
  --plan-mode algo --standoff 500 --vel 1.0 --boxes 35 --order arrival \
  --overhang 5 --algo-clearance 10 \
  --hm min_support_ratio=0.65 \
  --hm lookahead.k=4 --hm lookahead.rollouts=3 --hm lookahead.depth=8 \
  --hm drop_relief_mm=200 --hm drop_max_kg=3.5 \
  --seed 7
```

| 시드 | 적재/투입 | 버림 | 적재율 | knock | 팔레트 밖 | 낙하 | 판정 |
|---|---|---|---|---|---|---|---|
| 42 | **28/29** | **0** | **80.3%** | 6.4 | 5.4 | 3회 | 통과 |
| 7 | 28/32 | 3 | 73.1% | 8.2 | 8.0 | 1회 | 통과 |
| 99 | 29/32 | 2 | 73.2% | 5.4 | 2.9 | 2회 | 통과 |
| 평균 | **28.3** | | **75.5%** | ≤8.2 | ≤8.0 | | **3/3** |

**셋 다 `PALLET_FULL` 로 끝났다** — "자리를 못 찾아서" 가 아니라 팔레트가 실제로 찼다.
정정인님이 잰 천장이 "섞으면 59.9%, 종류별로 나누면 72.5%" 인데 **섞인 채로 75.5%** 다.

### 여기까지 온 순서

| | 적재율 | 평균 적재 |
|---|---|---|
| 기둥 억제 + 낙하 480 | 64.5% | 24.3 |
| 기둥 억제 **해제** | 70.9% | 26.7 |
| **+ 낙하 완화 200** | **75.5%** | **28.3** |

⚠ `drop_relief_mm` 는 로봇의 낙하 상한(`PL_DROP_MM`)보다 크면 안 되고, `drop_max_kg` 는
`PL_DROP_KG` 와 **같아야 한다.** 어긋나면 계획이 연 자리를 로봇이 거부한다.

⚠ 완화 200 / 350 / 500 이 데스크에서 **전부 같은 결과**다. 필요한 자리가 200 이면 다
열린다는 뜻이라 작은 값을 쓴다 — 계획이 여는 자리는 로봇이 실제로 놓을 수 있어야 한다.

★ **낙하는 실제로 1~3회만 걸렸다.** 완화가 한 일은 "떨어뜨리게" 가 아니라
  **"괜히 막던 자리를 풀어준" 것**에 가깝다. `_corridor_ok` 가 원래 과하게 보수적이었다
  (700 mm 협곡을 멀쩡히 내려간 실측과 같은 얘기다).

## 2. 어떻게 여기 왔나 (시드 7, 같은 조건에서 한 가지씩만 바꿈)

| | 적재 | 적재율 | knock | 팔레트 밖 | 판정 |
|---|---|---|---|---|---|
| 앞보기 k4 만 | 24 | 65.6% | 24.3 | 24.5 | **실패** |
| + 기둥 억제 | 24 | 64.0% | 27.4 | 25.6 | — |
| + 통로 반경 200 일괄 | 22 | 59.9% | 0.8 | — | 통과 |
| + 2단 통로 250/271 | 25 | 62.8% | 14.8 | 42.5 | — |
| + 낙하 (입구 위, 480 mm) | 26 | 65.9% | 3.2 | 22.2 | 통과 |
| **+ 낙하 (윗면 기준, 120 mm)** | **26** | **65.9%** | **0.6** | **1.5** | **통과** |

**통로를 조이는 길은 값을 치른다.** 반경 200 은 팔 걸림을 0회로 만들었지만 적재를
26 → 22 로 깎았다. 낙하는 **개수를 하나도 안 내주고** 그보다 낮은 knock 을 낸다.

### 낙하 높이가 결정적이다

입구 위(480 mm)에서 떨구면 박스가 흩어진다 — 팔레트 밖 22.2 mm.
**박스 윗면을 `rim − 그리퍼길이(150)` 까지 내리면** 120 mm 가 되고 1.5 mm 로 떨어진다.

근거는 `_corridor_ok` 주석에 이미 있던 것이다:
> 박스 윗면부터 그리퍼 길이(150)까지는 **그리퍼 몸통(Ø245)만** 지나가고,
> 그 몸통은 모든 박스 발자국 안에 들어간다 (3호 반폭 125 > 몸통 반경 122.5)

못 들어가는 것은 플랜지 **위**의 손목이다. 그러니 몸통 길이만큼은 슬롯에 넣어도 된다.

## 3. 기각한 것 — 코드는 남기고 **기본 꺼짐**

같은 아이디어가 다시 나왔을 때 재실행을 막으려고 이유를 함께 남긴다.

| 시도 | 왜 안 되나 |
|---|---|
| **IK 가지 재구성** (`PL_IK_SEEDS`) | 6축은 여유자유도가 0 이라 가지 사이에 연속 경로가 없다. 툴이 반드시 크게 휘둘린다 (실측 179° 스윙, 하강 구간에서 위험) |
| **이송 툴 기울기** (`PL_TOOL_TILT`) | 손목 중심에서 흡착면까지 271 mm 라 15° 에 70 mm 뿐. 팔뚝을 비키기엔 모자라고, 걸리는 곳이 하강 구간이라 발동 자체가 안 된다 |
| **통로 반경 상향** (`corridor_radius_mm`) | 반경 200 일괄은 적재율 −3.8%p. 얕은 이웃까지 200 을 요구해 멀쩡한 자리를 죽인다 |
| **2단 통로** (`corridor_tier2_*`) | 반경 일괄보다는 싸지만(−0.6%p) 걸림이 1회 남고 knock 14.8 mm |
| **손목/팔뚝 90° 회전** | 구면 손목이라 툴 자세를 고정하면 손목 해가 정/역 2개(=180°)뿐. 90° 라는 자세가 없다. 툴을 돌리면 **박스가 같이 돈다** |

## 4. ⚠ 검증 안 된 78.2% (번외)

`results/la4_s42_gui.txt` 가 **적재율 78.2% · 29개 이상**을 냈다. 위 채택안이 같은
시드 42 에서 60.5% 인 것과 비교하면 큰 차이다. 차이는 **기둥 억제 하나**다.

```
--standoff 500 --vel 1.0 --boxes 35 --order arrival --overhang 5 --algo-clearance 10
--hm min_support_ratio=0.65 --hm lookahead.k=4 --hm lookahead.rollouts=3 --hm lookahead.depth=8
--seed 42                       ← 기둥 억제 없음 · 낙하 없음 · 접촉 감지 없음
```

**그런데 이 숫자는 못 쓴다.** 이 실행은 로그 버퍼 버그(8192 바이트에서 잘림)를 고치기
전이라 34번에서 끊겼다. **요약 블록이 없어서 knock · 팔레트 밖 · RESULT 를 모른다.**
78.2% 는 33번째 사이클의 값이고, 그 더미가 서 있는 숫자인지 확인된 바 없다.

데스크는 기둥 억제가 시드 42 에서 26 → 25 라고 했는데 Isaac 은 29 → 22 다.
또 부호가 아니라 **크기**가 크게 어긋났다 (§10-1).

-> **로그가 고쳐졌으니 같은 조건을 다시 돌려 볼 것.** 78%가 진짜면 기둥 억제를
   빼는 쪽이 낫고, knock 이 크면 지금 채택안이 맞다.

## 5. 같이 고친 것

| 항목 | 내용 |
|---|---|
| **로그가 8192 바이트에서 잘렸다** | `Tee` 가 기본 버퍼로 파일을 열어, `--gui --hold` 를 Ctrl-C 로 끝내면 마지막 블록이 통째로 날아갔다. 저녁에 네 번 반복됐다 -> 줄 단위 + 매 write flush |
| **`--diag-knock` 이 죽었다** | 변위 벡터 `_d` 를 바로 아래에서 박스 깊이 `_d` 가 덮어써 `for v in _d` 가 float 을 훑었다. 하필 **첫 knock 이 나는 순간**이라 진단이 한 줄도 안 남았다 |
| **놓고 나서 아래로 내려갔다** | 후퇴가 `put_top + approach` 고정이라, 협곡 입구에서 떨구면 팔이 이미 그보다 위인데 다시 내려갔다. §10-3 과 같은 부류 -> 셋 중 최대로 |
| **크게 막힐수록 더 오래 밀었다** | 정체 탈출에 `err < 50 mm` 조건이 붙어 있어, 잔차 55.6 mm 면 탈출이 안 걸리고 2.5 초를 눌렀다 -> 크기와 무관하게 즉시 힘을 뺀다 |
| **`--hm` 이 중첩 키를 못 받았다** | 앞보기가 dict 라 스칼라 문법으로는 손댈 수 없었다 -> `--hm lookahead.k=4` |
| **`scripts/summarize_runs.py`** | 로그에서 **조건과 결과를 한 줄로** 뽑는다. 하루에 30번 넘게 돌리면 "그 숫자가 어느 조건이었나" 를 놓친다 |
