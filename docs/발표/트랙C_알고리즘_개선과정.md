## 1. 알고리즘 튜닝 과정 (고정 시드 기반)

모든 실험은 **random_seed 고정** 상태에서 파라미터를 하나씩 바꿔가며 진행했다.
"이전 단계와 정확히 같은 박스 시퀀스"에서 어떤 파라미터가 결과를 바꾸는지 추적할 수 있다.

### 1-1. 단계별 개선 흐름 (시간 순)

```
[기준선]  DBLF 순차 배치 (회전 없음)
   │
   ▼  ② Heightmap + 가중합 도입
   │     w_height=0.6 · w_support=0.4 · w_wall=0.2 · w_far=0.1
   │
   ▼  ③ _corridor_ok 로봇 통로 검사 추가
   │     팔(Ø245mm)이 물리적으로 못 가는 자리를 사전 차단
   │
   ▼  ④ min_support_ratio 0.7 → 0.65
   │     100% 지지율에서 버려지던 박스 구제
   │
   ▼  ⑤ Lookahead Rollout 도입
   │     k=4 · rollouts=3 · depth=8
   │
   ▼  ⑥ w_level=0.05 (절벽 방지 항) 추가
   │     시드 3집합 교차검증으로 검증
   │
   ▼  ⑦ plan_clearance_mm=10 도입
   │     간격 0은 물리적 성립 불가 (접촉 오프셋+배치 오차)
   │
   ▼  ⑧ 기둥 억제 해제
   │     tower_ring 제거 → Isaac에서 적재 +4~6개
   │
   ▼  ⑨ drop_relief_mm=200 · drop_max_kg=3.5 (낙하 완화)
         가벼운 박스에 한해 통로 규칙 완화 → 최대 단일 개선
```

## 2. 학술 대조군 — Extreme Point (EP) 알고리즘과의 비교 실측

### 2-1. 왜 Extreme Point (EP) 인가?
- **학술적 위치**: Crainic et al. (2008, *INFORMS JoC*) 논문 발표 이후 3D Bin Packing 분야에서 **가장 널리 인용되는 글로벌 표준 대조군(Standard Baseline)**.
- **구조적 차이점**:
  - **Extreme Point (EP)**: 공간에 박스가 배치될 때 발생하는 3D 모서리 **"이산적인 점(Discrete 3D Points)" 좌표 목록**만 관리.
  - **제안 알고리즘 (Heightmap)**: 팔레트 전체를 10mm 격자로 나눈 **"연속적인 2.5D 표면 지형(Surface Grid)"**으로 공간을 관리.

### 2-2. 30개 시드 실측 수치 비교 (포화 기준)

| 알고리즘 구분 | 적재 개수 (30시드 평균) | 적재율 (용량 기준) | 실제 높이 적재율 | 비고 & 로봇팔 물리 연동 결과 |
|---|---|---|---|---|
| **제안 (Heightmap + Lookahead)** | **20.2 ± 3.0 개** | **59.1%** | **60.1%** | **안정적 적재 (Isaac 실측 3시드 75.5% 달성, 탑 붕괴 0회)** |
| **Extreme Point (통로검사 미적용)** | 25.4 ± 4.7 개 | 141.2% | 142.4% | 순수 3D 극점만 채워 비정상 높이 솟구침 및 **로봇팔 대량 충돌/붕괴** |
| **Extreme Point (통로검사 적용)** | 24.5 ± 4.5 개 | 137.7% | 139.2% | 로봇 통로 제약 적용 시 극점 소멸 및 불완전 지형 붕괴 |
| **베이스라인 (DBLF 순차)** | 14.2 ± 3.2 개 | 41.4% | 43.1% | 회전 없이 왼쪽 아래부터 채움 (단순 순차 대조군) |

### 2-3. Extreme Point (EP) 대비 제안 알고리즘의 우위 분석
1. **표면 평탄화(`w_level`) 및 미래 예측(Lookahead)의 부재**:
   - EP 알고리즘은 3D 공간 상에서 AABB 겹침만 없으면 좁은 극점에 박스를 집어넣어, 표면 지형이 급격한 "절벽"을 형성함.
   - 이로 인해 실물/시뮬 환경에서 높은 기둥이 솟구치다 무너지거나, 이웃 박스가 공중에 뜨는 현상 발생.
2. **로봇 팔 기하 제약(`_corridor_ok`)과의 결합 문제**:
   - EP는 좌표 점만 다루므로 그리퍼(Ø245mm)가 내려갈 수 있는 수직 통로를 고려하지 못함.
   - 통로 검사를 강제하면 극점 후보가 급격히 사라져 알고리즘의 본래 이점이 상실됨.

## 3. 최종 채택 파라미터 정본

```bash
PL_CONTACT_STOP=1 PL_DROP_KG=3.5 \
~/isaac-sim-5.1.0/python.sh scripts/demo_stack15.py \
  --plan-mode algo --standoff 500 --vel 1.0 --boxes 35 --order arrival \
  --overhang 5 --algo-clearance 10 \
  --hm min_support_ratio=0.65 \
  --hm lookahead.k=4 --hm lookahead.rollouts=3 --hm lookahead.depth=8 \
  --hm drop_relief_mm=200 --hm drop_max_kg=3.5 \
  --seed 42
```

| 파라미터 | 값 | 채택 근거 |
|---------|-----|---------|
| `min_support_ratio` | **0.65** | 0.7에서 버려지던 박스 구제. 3시드 비교로 확인 |
| `lookahead.k/rollouts/depth` | **4/3/8** | plan() 163ms. 로봇 모션 8s 대비 2% |
| `plan_clearance_mm` | **10** | 0mm는 물리적 성립 불가. 10에서 전부 통과 |
| `drop_relief_mm` | **200** | 200/350/500 전부 같은 결과. 작은 값 사용 |
| `drop_max_kg` | **3.5** | 3호(3kg)만 대상. 4호 5kg는 낙하 충격 위험 |
| `w_height` | **0.6** | 바닥부터 채움 — 무게중심 안정 |
| `w_support` | **0.4** | 밑면 지지 우선 |
| `w_wall` | **0.2** | 가장자리 밀착 |
| `w_far` | **0.1** | 먼 쪽부터 (로봇 기하 유래, 논문에 없는 항) |
| `w_level` | **0.05** | 절벽 억제. 시드 3집합 교차검증 |
| `overhang` | **5mm** | 벽 쪽 간격 손해 보상 (데모 전용) |

## 4. 발표 스토리보드 (Storytelling)

```
① 문제 정의
   "온라인 3D 빈 패킹 + 6축 로봇 팔 기하 제약" (교과서 오프라인 문제와 다른 3가지)

② 대조군 알고리즘 선정
   - 단순 순차 (DBLF): 회전 없는 단순 배치 대조군 (41.4%)
   - Extreme Point (EP, Crainic et al. 2008): 3D BPP 논문들의 글로벌 대표 표준 대조군

③ EP 알고리즘의 로봇팔 연동 시 한계 증명
   - EP는 순수 3D 공간 극점만 다뤄 표면 절벽 형성을 막지 못함
   - 로봇 팔(그리퍼 Ø245mm) 진입 통로 미고려로 시뮬 환경에서 탑 붕괴/충돌 대량 발생

④ 우리 알고리즘의 성과 (Heightmap + Lookahead + _corridor_ok + drop_relief)
   - 표면 평탄화(w_level) + 앞보기(Lookahead) + 통로검사 + 자유낙하 완화 결합
   - Isaac Sim 3시드 실측 평균 75.5% 적재율 달성 (종류별 분할적재 천장 72.5% 돌파)
```
