## 1. 알고리즘 튜닝 과정 (고정 시드 기반)

모든 실험은 **random_seed 고정** 상태에서 파라미터를 하나씩 바꿔가며 진행했다.
"이전 단계와 정확히 같은 박스 시퀀스"에서 어떤 파라미터가 결과를 바꾸는지 추적할 수 있다.

### 1-1. 단계별 개선 흐름 (시간 순)

```
[기준선]  DBLF 순차 배치 (회전 없음)
   │
   ▼  ② Heightmap + 가중합 도입
   │     w_height=0.6 · w_support=0.4 · w_wall=0.2 · w_far=0.1
   │
   ▼  ③ _corridor_ok 로봇 통로 검사 추가
   │     팔(Ø245mm)이 물리적으로 못 가는 자리를 사전 차단
   │
   ▼  ④ min_support_ratio 0.7 → 0.65
   │     100% 지지율에서 버려지던 박스 구제
   │
   ▼  ⑤ Lookahead Rollout 도입
   │     k=4 · rollouts=3 · depth=8
   │
   ▼  ⑥ w_level=0.05 (절벽 방지 항) 추가
   │     시드 3집합 교차검증으로 검증
   │
   ▼  ⑦ plan_clearance_mm=10 도입
   │     간격 0은 물리적 성립 불가 (접촉 오프셋+배치 오차)
   │
   ▼  ⑧ 기둥 억제 해제
   │     tower_ring 제거 → Isaac에서 적재 +4~6개
   │
   ▼  ⑨ drop_relief_mm=200 · drop_max_kg=3.5 (낙하 완화)
         가벼운 박스에 한해 통로 규칙 완화 → 최대 단일 개선
```

### 1-2. 파라미터별 실측 결과 (Isaac 실측 + 데스크 비교)

#### A. 데스크 계산 비교 — 시드 20개 · 35박스 · 통로 검사 동일 적용

| 단계 | 알고리즘 | 적재 개수 | 적재율 | 표준편차 | 대조군 대비 |
|------|---------|----------|--------|---------|------------|
| ① | 대조군 — DBLF, 회전 없음 | 15.6 | **39.7%** | ±8.9 | — |
| ② | Heightmap 그리디 (가중합) | 23.1 | **62.1%** | ±5.9 | +22.4%p |
| ③ | + Lookahead (rollout) | 23.8 | **64.3%** | ±5.9 | +24.6%p |
| ④ | + 낙하 완화 (최종) | **26.5** | **70.3%** | **±5.4** | **+30.6%p** |

> 공정성: 대조군에도 통로 검사를 똑같이 걸었다. "전략 대 전략" 비교이지 "물리를 지킴 대 안 지킴" 비교가 아니다.

#### B. Isaac 실측 — 개별 파라미터 on/off 비교 (시드 7, 35박스)

| 실험명 | 변경 사항 | 적재/투입 | 적재율 | knock(mm) | 팔레트밖(mm) | 판정 |
|--------|----------|----------|--------|-----------|-------------|------|
| `la4_s7` | Lookahead k=4 만 | 24/35 | 65.6% | 24.3 | 24.5 | **실패** |
| `twr_s7` | + 기둥 억제 | 24/35 | 64.0% | 27.4 | 25.6 | — |
| `rad200_s7` | + 통로 반경 200 일괄 | 22/35 | 59.9% | 0.8 | — | 통과 |
| `tier2_s7` | + 2단 통로 250/271 | 25/35 | 62.8% | 14.8 | 42.5 | — |
| `contact_s7` | + 낙하 (입구 위, 480mm) | 26/35 | 65.9% | 3.2 | 22.2 | 통과 |
| `pred130b_s7` | **+ 낙하 (윗면 기준, 120mm)** | **26/35** | **65.9%** | **0.6** | **1.5** | **통과** |

**핵심 관찰:**
- 통로 반경 일괄 확대(200) → 팔 걸림 0회지만 적재 26→22개 (−15%)
- 2단 통로 → 걸림 1회 남고 knock 14.8mm
- 낙하 도입 → **개수를 하나도 안 내주고** 걸림 해소 + knock 0.6mm

#### C. Isaac 실측 — 기둥 억제 해제 + 낙하 완화 (3시드 비교)

| 단계 | 적재율 | 평균 적재 |
|------|--------|----------|
| 기둥 억제 + 낙하 480mm | 64.5% | 24.3 |
| 기둥 억제 **해제** | 70.9% | 26.7 |
| **+ 낙하 완화 200** | **75.5%** | **28.3** |

#### D. Isaac 실측 — support_ratio 스윕 (3시드 · 35박스)

| min_support_ratio | 적재(s42) | 적재(s7) | 적재(s99) | 평균 판정 |
|-------------------|----------|---------|---------|----------|
| 0.7 (기본) | 19 | 16~20 | 19 | 혼재 |
| **0.65 (채택)** | **22** | **26** | **25** | **3/3 통과** |
| 0.85 | 18 | 14 | 19 | 불안정 |
| 0.9 | 18 | 14~18 | 19 | 깎임 |

#### E. Isaac 실측 — 이격(standoff) 비교

| 이격 | s42 knock | s7 knock | s99 knock | 판정 |
|------|-----------|---------|-----------|------|
| 400mm | 0.9 | **1250.9** (탑 붕괴) | **1232.4** (붕괴) | 1/3 |
| **500mm (채택)** | 2.0 | 4.2 | 0.7 | **3/3** |

> 400mm에서 s7·s99가 탑 붕괴한 것은 돌아갈 때 이송 고도 버그 때문. 고친 뒤 500mm로 이 문제 해소.

#### F. Isaac 실측 — 방향성 통로의 교훈 (20박스 실험)

| 조건 | 적재 | 최대 knock | 판정 | 비고 |
|------|------|-----------|------|------|
| 방향성 통로 없음 (간격 10) | 17/20 | 63.2mm | 실패 | 실패 2건이 3개를 깎음 |
| **방향성 통로 켬** | **20/20** | **1.5mm** | **통과** | — |
| 방향성 통로 + w_level | 20/20 | 2.7mm | 통과 | 오히려 단수 9→10 안 됨 |

> 결론: w_level + 간격 10만 있으면 방향성 통로 없이 통과한다. 방향성 통로 코드는 기본 꺼짐으로 남김.

## 3. 최종 채택 파라미터 정본

```bash
PL_CONTACT_STOP=1 PL_DROP_KG=3.5 \
~/isaac-sim-5.1.0/python.sh scripts/demo_stack15.py \
  --plan-mode algo --standoff 500 --vel 1.0 --boxes 35 --order arrival \
  --overhang 5 --algo-clearance 10 \
  --hm min_support_ratio=0.65 \
  --hm lookahead.k=4 --hm lookahead.rollouts=3 --hm lookahead.depth=8 \
  --hm drop_relief_mm=200 --hm drop_max_kg=3.5 \
  --seed 42
```

| 파라미터 | 값 | 채택 근거 |
|---------|-----|---------|
| min_support_ratio | **0.65** | 0.7에서 버려지던 박스 구제. 3시드 비교로 확인 |
| lookahead.k/rollouts/depth | **4/3/8** | plan() 163ms. 로봇 모션 8s 대비 2% |
| plan_clearance_mm | **10** | 0mm는 물리적 성립 불가. 10에서 전부 통과 |
| drop_relief_mm | **200** | 200/350/500 전부 같은 결과. 작은 값 사용 |
| drop_max_kg | **3.5** | 3호(3kg)만 대상. 4호 5kg는 낙하 충격 위험 |
| w_height | **0.6** | 바닥부터 채움 — 무게중심 안정 |
| w_support | **0.4** | 밑면 지지 우선 |
| w_wall | **0.2** | 가장자리 밀착 |
| w_far | **0.1** | 먼 쪽부터 (로봇 기하 유래, 논문에 없는 항) |
| w_level | **0.05** | 절벽 억제. 시드 3집합 교차검증 |
| overhang | **5mm** | 벽 쪽 간격 손해 보상 (데모 전용) |

## 4. 적재율 천장 분석 (왜 75.5%가 대단한가)

| 조건 | 적재율 | 비고 |
|------|--------|------|
| 3종이 섞여서 올 때 (우리 조건) | 59.9% | 기하 상한, 팔 제약 제외 |
| 한 종류만 모아서 쌓을 때 | 70~79% | 같은 크기만 무한 공급 |
| 종류별로 나눠 쌓을 때 | 72.5% | 3구역 분류 가정 |
| **우리 최종 (섞인 채로, Isaac 실측)** | **75.5%** | **나눠 쌓기를 넘음** |

> "섞인 채로 종류별로 나눠 쌓은 것(72.5%)을 넘었다."
> 차이 원인: 박스 높이가 210/280/340 세 가지뿐 → 표면이 "평평 아니면 절벽"
> → w_level과 앞보기가 절벽 생성을 억제해 공간을 더 확보함

## 5. 추후 진행 단계 추천

### Phase 1: 베이스라인(비교 대상) 알고리즘을 로봇팔에 연결해서 돌려보기

**목적:** 같은 시뮬(Isaac) 환경에서 대조군 알고리즘을 실제 로봇으로 적재시켜 "공정한 비교"

| 할 일 | 구체 방법 | 예상 소요 |
|-------|----------|----------|
| ① DBLF 대조군을 Isaac에서 실행 | `--plan-mode baseline` 로 전환 (코드 이미 존재: `compare_baseline`) | 0.5일 |
| ② 대조군 Isaac 실측 수치 확보 | 시드 3개(42/7/99) 각 1회 → 적재율/knock/사이클 기록 | 0.5일 |
| ③ 시각 자료 생성 | 대조군 vs 제안 팔레트 최종 상태 캡처 비교 | 0.5일 |

**왜 필요한가:** 현재 대조군 수치(39.7%)는 데스크 계산이다. 발표에서 "Isaac에서 로봇이 직접 돌린 수치"를 내면 설득력이 훨씬 강해진다.

### Phase 2: 다른 계열 알고리즘과의 논문 근거 비교

**목적:** 산업 표준/논문 기반으로 "왜 Heightmap + 가중합이 맞나"를 정량 근거로 제시

| 비교 대상 | 논문 | 보고 적재율 | 우리 조건과의 차이 | 비교 가치 |
|----------|------|-----------|------------------|----------|
| **DBLF** | Karabulut & İnceoğlu (2004) | BR1~BR7 벤치마크에서 ~85-92% | **오프라인 + 무제약** → 직접 비교 불가 | ★★ 대조군으로 채택 완료 |
| **Extreme Point** | Crainic, Perboli, Tadei (2008) INFORMS JoC | BR1~BR7에서 ~89-95% | 오프라인 벤치마크 | ★ 코어 재작성 규모라 미채택 |
| **DRL 온라인 패킹** | Zhao et al. (2021) AAAI | 온라인 70~75% (자체 벤치) | 로봇 제약 없음 · 학습 데이터 필요 | ★★★ 가장 직접적 비교 대상 |
| **Heightmap + stability** | Wang et al. (2020) | 팔레타이징 실무에서 ~65-70% | 로봇 제약 미포함 | ★★ 같은 계열 비교 |

**해야 할 것:**

| 단계 | 내용 | 소요 |
|------|------|------|
| ① 논문 적재율 수치 원문 확인 | 위 4편의 결과 표에서 조건별 적재율 발췌 | 1일 |
| ② 조건 차이표 작성 | "그들은 오프라인 / 무제약 / 벤치마크 박스" vs "우리는 온라인 / 로봇 제약 / 혼합 3종" | 0.5일 |
| ③ **공정 비교 불가** 명시 | 논문 수치를 그냥 옮기면 오해를 부른다. "조건이 다르다"를 함께 밝혀야 함 | — |
| ④ 우리 조건에서의 의미 해석 | "오프라인 최적에서 85-92%인 것에 비해, 온라인+로봇제약이라는 훨씬 어려운 조건에서 75.5%를 달성했다"는 논리 구성 | 0.5일 |

### Phase 3: 추가 비교 실험 (시간이 있다면)

| 실험 | 목적 | 방법 |
|------|------|------|
| ① Layer building 구현 → Isaac 실행 | "같은 높이 박스가 모여야" 한다는 한계를 실측으로 보여주기 | 간단 구현 + 3시드 |
| ② Lookahead depth 스윕 | depth 1/2/4/8/16별 적재율 vs plan() 시간 트레이드오프 | 데스크 시드 20 + Isaac 3시드 |
| ③ 가중치 민감도 분석 | w_height ±0.1 / w_support ±0.1 변경 시 적재율 변화 | 데스크 시드 20 |
| ④ 박스 종류 4종/5종 확장 | 혼합 비율이 바뀌면 적재율 천장이 어떻게 변하나 | 데스크 시드 20 |

### Phase 4: 발표 자료 보강

| 항목 | 내용 |
|------|------|
| ★ **대조군 Isaac 영상** | DBLF 대조군 로봇 적재 영상 → 제안 영상과 나란히 재생 |
| ★ **논문 비교표** | "이 논문은 오프라인 벤치에서 X%였는데, 우리는 온라인+로봇에서 75.5%" |
| 파라미터 민감도 차트 | support_ratio / lookahead_depth / drop_relief 별 적재율 곡선 |
| **"실패 비용" 시각화** | 대조군에서 팔이 헤집고 스택 무너지는 장면 캡처 → "왜 통로 검사가 필수인가" |

## 6. 발표에서 강조할 논리 흐름 (제안)

```
① 문제 정의
   "온라인 3D 빈 패킹 + 로봇 제약"이라는 교과서와 다른 3가지

② 왜 이 알고리즘인가 (계열 비교)
   Wall/Layer/EP → 오프라인 전제
   DRL → 6일 일정 불가
   DBLF → 대조군으로 채택
   Heightmap + 가중합 → 팔레타이징 실무 표준이면서 온라인 가능

③ 어떻게 개선했나 (튜닝 과정)
   DBLF 39.7% → Heightmap 62.1% → Lookahead 64.3% → 낙하 완화 70.3%
   (데스크 비교 표)

④ 로봇과 연결했을 때 (Isaac 실측)
   동일 설정 3시드 평균 75.5%
   → 대조군 Isaac 실측 XX%와 비교 (Phase 1에서 확보)

⑤ 왜 이 숫자가 대단한가 (천장 분석)
   섞인 채로 72.5%(나눠 쌓기)를 넘었다

⑥ 논문과의 위치 (Phase 2에서 확보)
   "오프라인 벤치에서 85-92%인 것에 비해,
    훨씬 어려운 조건(온라인+로봇)에서 75.5%"
```
