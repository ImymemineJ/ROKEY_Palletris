# 스마트 물류창고 로봇팔 상차 시스템

## 프로젝트 개요

택배 상자를 자동 인식·분류해 팔레트에 적재하고, 사람 개입 없이 1t 트럭에 상차하는 시스템.
출처: `C-3_0820_아침 브리핑 3c17f17722138015ac8ddeec0c402c82.md`

## 시스템 파이프라인

| 단계 | 내용 |
|---|---|
| 1 · 투입 | 택배가 1차 컨베이어에 올라온다 |
| **2 · 3D 인식** | **행선지(색 R/G/B)와 규격(W·L·H)을 함께 읽는다** — 1차는 치수만, 자세 제외 |
| **3 · 관제탑** | **읽은 내용을 보관하고 각 로봇에 배치를 지시한다** |
| 4 · 2차 컨베이어 | 배정된 구역의 3라인 중 1라인으로 분기 |
| 5 · 로봇 적재 | 구역 담당 H2017 이 구역별 팔레트에 적재 |
| 6 · 상차 | 옆문 전면 개방 · 푸셔로 팔레트째 무인 상차 |

> 도면: `도면/1-전체플로우.png` · `Pasted image.png`는 **옛 구조**이므로 쓰지 않는다.

**핵심 전제**: 2차 컨베이어 3갈래는 서로 독립적으로 동시 동작한다.
따라서 **처리량은 로봇 1대 속도가 아니라 3대 병렬 속도로 결정된다.**
성능을 논할 때는 항상 이 병렬 기준을 쓴다.

## 핵심 기능 5가지

| 기능 | 처리 | 출력 |
|---|---|---|
| 구역 배정 · 분류 | 배송지 기준으로 A/B/C 담당 구역 판정 | 2차 컨베이어 3라인 중 1라인 |
| 실시간 3D 인식 | 1차 컨베이어 위 택배를 읽는다 | **박스 치수 W·L·H** (1차) / + 자세 (2차) |
| 온라인 배치 결정 | 하이트맵에서 높이 + 평탄도를 **함께** 평가 | 배치 좌표 · 하이트맵 갱신 |
| 병렬 팔레트 적재 | 구역 담당 로봇팔이 적재 | 3대 동시 병렬 적재 |
| 무인 측면 상차 | 옆문 전면 개방 후 팔레트째 상차 | 사람 개입 0 |

## 개발 단계

**1차 (현재 목표)**
1. **A/B/C 구역 분류 및 3라인 분기**
2. **실시간 3D 인식 — 치수(W·L·H) 측정까지만**
3. 온라인 패킹 알고리즘 구현
4. 로봇 3대 병렬 적재 구현
5. 팔레트 → 1t 트럭 측면 상차 프로세스 연동

**2차 — 정확도·안정성 고도화**: 구역 배정 규칙 최적화, 지지 안정성 향상
+ **자세(회전) 추정 추가**, 송장 바코드 인식, 박스 랜덤 yaw 스폰

**3차 — 전체 시스템 최적화**: 다차원/다경로 물류 흐름 확장, 디지털 트윈 기반 실시간 모니터링 UI

> 1차 5개 항목이 끝나기 전에는 2·3차 항목을 먼저 건드리지 않는다.

전체 수치는 [시스템 사양서](C-3_0820_시스템_사양서.md) 참조. 아래는 자주 쓰는 값만.

| 설치 | 받침대 약 **700mm** 위, 파렛트 이격 200~300mm |

| 모션 | **Lula / RMPflow** (MoveIt2 백업) · 경유점 방식 필수 |

| 3D 인식 범위 | **1차 = 치수(W·L·H)만.** 자세 추정은 2차 |
| 박스 투입 자세 | **1차는 축 정렬(yaw = 0) 고정 스폰.** 랜덤 yaw는 2차 |
| 트럭 | 1t, 적재공간 **2,800 × 1,600 × 1,600 mm**, 옆문 전면 개방 |
| 파렛트 | 1200 × 800 — 트럭에 **길이 방향 일자 3개** (바닥 활용률 64%) |
| 레이아웃 | 3라인 병렬 폭 **약 6.9 m** (피치 2.3 m) · 로봇 3대는 **컨베이어 같은 쪽 한 방향** |
| **높이 기준** | **원점 z=0 ≡ 도크 바닥 ≡ 트럭 적재함 바닥.** 지면은 z−850mm |
| 상차 푸셔 | 끝단 캐리지 · 스트로크 **약 1,300** · **1,400 N 급** · 트럭 바닥은 **저마찰 판 + 스토퍼** |
| 적재 상단 | z = 1,450mm (내高 1600 − 파렛트 150) |
| 환경 | Ubuntu 24.04 · ROS 2 Jazzy · Isaac Sim · `~/cobot3_ws` |
| **목표 적재율** | **65 %** (최소 55 / 우수 72) |
| **목표 사이클** | **12 초/박스** → 3대 병렬 **900 개/h** |
| 로봇 에셋 | `github.com/Jik-Kim/doosan-robot2` (jazzy) — `dsr_description2`, `dsr_moveit_config_h2017` |

### 사양을 다룰 때 지킬 것

- **박스는 처음부터 3종을 섞어 투입한다.** 1종 예비 단계는 없다.
- **박스 규격을 코드에 하드코딩하지 않는다.** 설정 파일(`boxes.yaml`)의 배열로만 읽는다.
- **흡착은 릴리스 후 보정이 불가능하다.** 패킹은 "놓는 순간 확정"을 전제로 작성한다.
- **박스 중량 상한은 가반하중(18kg)이 아니라 흡착력·상판 강성(10kg)이 정한다.**
- **USD만 복사하면 IK가 붙지 않는다.** URDF + descriptor(또는 MoveIt config)를 세트로 옮긴다.
- **관제탑이 상태를 보관한다.** 인식은 읽기만, 로봇은 실행만. 상태는 관제탑 한 곳에 둔다.
- **트럭 바닥에 자유 롤러를 두지 않는다.** 주행 중 파렛트가 유동하면 적재가 무너진다.
- **컨베이어·흡착 그리퍼는 Isaac 내장 익스텐션을 쓴다** (`isaacsim.asset.gen.conveyor`, `isaacsim.robot.surface_gripper`). 직접 만들지 않는다.
- **로봇 셀은 픽 지점과 파렛트를 정면 같은 쪽에 둔다.** 뒤에서 집어 앞에 놓으면 joint_1이 180° 돌아 라인 피치가 2.3 m → 3.4 m 로 뛴다.
- **구역 판정을 "정답 그대로 통과"로 구현하지 않는다.** 1차에서도 색 태그로 실제 판정한다.
- **1차에서 인식은 치수만 낸다.** 박스가 축 정렬로 스폰되므로 자세는 항상 yaw=0으로 가정한다.
  이 가정을 결과 문서에 반드시 명시한다.
- **"자세"와 "배치 회전"은 다른 값이다.** 자세는 B의 인식 출력(1차 제외), 배치 회전은 C의 결정 출력(1차 포함).
- **성능 수치는 1회 실행값을 쓰지 않는다.** 최소 20회 반복 후 **평균 ± 95% 신뢰구간**으로 보고한다.
- **사이클 타임에 M0609 측정값을 재사용하지 않는다.** H2017은 joint_1~3 속도가 35~45% 낮다.
- **도달범위·적재율 수치를 바꿀 때는 사양서 §9 변경 이력에 남긴다.**

## 작업 규칙

- **온라인 전제**: 박스는 실시간으로 랜덤하게 들어온다. 전체 목록을 미리 알고 푸는 오프라인 해법을 기본값으로 쓰지 않는다. 오프라인 값을 낼 때는 "상한 대조군"임을 반드시 명시한다.
- **배치 평가**: 높이만 보지 않는다. 높이와 평탄도를 함께 본다.
- **산출물**: 문서는 `.md`로 작성한다. 그림은 문서에 인라인으로 넣지 말고 별도 폴더에 `.png`로 모아 링크한다.
- **언어**: 문서·주석·커밋 메시지는 한국어로 쓴다.
- **수치**: 적재율·처리량 같은 숫자를 문서에 적을 때는 어떤 조건에서 나온 값인지(온라인/오프라인, 시행 횟수)를 함께 적는다.

### Isaac Sim 실행 가능 장비 — 총 3대

| 장비 | Isaac Sim | 사용자 |
|---|---|---|
| GPU 노트북 1번 (5080) | ✅ | **김학민 (A)** |
| GPU 노트북 2번 (5080) | ✅ | **정정인 (B)** |
| 김병직 개인 노트북 (RTX 5060) | ✅ | **김병직 (D)** |
| 민범진 개인 노트북 | ❌ | 민범진 (C) — Isaac 불필요 |

- 5060은 VRAM 8GB로 **최소 사양 수준**이다. 로봇 1대 + IK 검증(D)에는 충분하나,
  전체 씬 + 로봇 3대 + 카메라(A)에는 부족하므로 **A에게 5080을 준다.**
- **Isaac 필요 인원 3명 = 가능 장비 3대.** 여유가 없으므로 장비를 서로 바꾸지 않는다.
