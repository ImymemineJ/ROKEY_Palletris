## 2. 좌표 (실측 · Isaac BBoxCache)

```
                    본선  X 0 -> -23204,  Y -773~773,  롤러면 z 800
   스폰 [-409,-66]  ─────────────────────────────────────────▶ (-X)
                        │            │            │
                     분기 A       분기 B       분기 C          <- 위치변환 레일
                        │            │            │
                     지선 A(+Y)   지선 B       지선 C
                        │            │            │
                    [스토퍼 Y 4181]
                        ●  로봇 (지선중심, 5076, z 1250)
              팔레트 ◀──┘  (로봇 -X 쪽 400 mm)
                        │
                    셀 컨베이어 (+Y, 프레임 1000)
                        │
                        └────▶ 합류 라인 (+X, 프레임 1200) ──▶ 트럭
```

| 항목 | A | B | C |
|---|---|---|---|
| 지선 롤러 X | −8381~−6810 | −14381~−12810 | −20381~−18810 |
| 로봇 베이스 | (−7596, 5076, 1250) | (−13596, …) | (−19596, …) |
| 팔레트 (상면 950) | X −8796~−7996 | −14796~−13996 | −20796~−19996 |
| 셀 컨베이어 X | −8896~−7896 | −14896~−13896 | −20896~−19896 |
| 합류 라인 Y중심 | 8901 | 10101 | 11301 |
| 합류 라인 X | −8896~−2400 | −14896~−2400 | −20896~−2400 |

공통: 지선 끝(스토퍼) Y **4181** · 로봇 Y **5076** (= 지선끝 + 895, test1-1 규칙)
팔레트 Y 4476~5676 · 롤러면 z **800** · 적재함 Y **8301~11901 (3600)**

### 왜 이 숫자인가

- **팔레트가 로봇 옆(−X)에 있다.** test1-1 에서 팔레트는 벨트 **옆**이라 로봇 스윙이
  90°다. 지선 뒤에 두면 180°가 되는데, 흡착 패드에 매달린 박스는 감쇠가 0이라
  스윙이 클수록 착지가 흔들린다 (CLAUDE.md 실측 22~76 mm).
- **팔레트는 1200 × 800 그대로**다. 지선이 +Y 라 월드에서 90° 돌아 있을 뿐이다
  (월드 X 800 · 월드 Y 1200). `test_3.yaml` 의 `pallet.width/depth` 가 그것을 담는다.
- **이격 400** (2026-08-24 팀 합의). test1-1 은 Y 로 뺐지만 여기선 X 로 뺀다.
- **페데스탈 1250.** 팔레트가 셀 컨베이어 위(950)라 로봇 베이스보다 높다. 이격이
  400 이 되면서 1200 으로는 최원점 **1703.7 mm** 로 도달 1700 을 3.7 mm 넘겼다.
  1250 이면 **1673.3**, 여유 26.7 mm. 픽업은 901.7 이라 넉넉하다.
- **셀 컨베이어 프레임 1000.** 페데스탈(로봇 X ± 200)을 피하려면 반폭 ≤ 500 이다.
- **합류 라인 프레임 1200 · 적재함 3600.** 팔레트를 코너에서 안 돌리기로 했으므로
  합류 라인을 가로지르는 치수가 팔레트의 Y 변 1200 이다. 1200 × 3 = 3600.
  ⚠ **1 톤 트럭 폭(2800)이 아니다.** 코너에 턴테이블을 넣으면 800 × 3 = 2400,
  피치 1000 으로 2800 에 정확히 들어간다 — 그때 되돌리면 된다.

## 3. 씬에서 찾아 고친 것 — 전부 "에러 없이 조용히 안 도는" 부류

컨베이어를 GUI 로 복제한 뒤 원본(`/World/ConveyorTrack_02`)을 지워서 그래프가 죽어 있었다.

| 대상 | 증상 | 조치 |
|---|---|---|
| 지선·본선 그래프 6 개 | `conveyorPrim` 이 없어진 prim 을 가리킴 | 자기 롤러로 재연결 (관계 12 개) |
| 같은 그래프 6 개 | **연결선**(`onStep`/`delta`/`velocity`)도 죽은 경로 → 노드가 틱조차 안 됨 | 자기 그래프로 재연결 (**18 개**) |
| 합류 라인 3 개 | `conveyorPrim` 이 **본선 롤러**를 가리킴 → 합류는 정지, 본선만 3 배 | 재연결 |
| 셀 컨베이어 3 개 | `Velocity` 변수에 값 없음(`authored=False`) | 0.0 으로 authoring |
| 분기점 프레임 | 롤러면 위 **23 mm 턱**이 꺾인 박스를 막음 | 프레임 충돌 끔 + 레일 3 쌍 신설 |

> **교훈.** OmniGraph 는 관계(relationship)와 **연결선(connection)** 이 따로다.
> 관계만 고치면 노드가 대상은 알지만 **호출되지 않는다.** 둘 다 봐야 한다.

## 4. 위치변환 레일 (색상 라우팅)

박스 크기(= 색: `BoxNo3/4/5`)로 목적지를 정한다. **3호 → A · 4호 → B · 5호 → C.**

분기점 전용 짧은 벨트를 넣을 수 **없다** — 본선과 지선이 프레임 메시
`SM_ConveyorBelt_A23` 를 L 자 한 덩어리로 공유해서, 본선 쪽만 떼면 지선 측면 레일까지
사라진다. 대신 **본선 조각 하나에 분기점이 정확히 하나씩** 있다:

| 조각 | X 범위 | 분기 |
|---|---|---|
| `ConveyorTrack_09` | −11204~−4279 | A |
| `ConveyorTrack_08` | −17204~−10279 | B |
| `ConveyorTrack_03` | −23204~−16279 | C |

그래서 그 조각의 **표면속도 방향을 통째로 −X ↔ +Y 로 꺾는다.** 그게 위치변환 레일이다.
`conveyor_ctl.set_direction(seg, world)` 가 월드 방향을 각 조각 로컬 축으로 환산해 쓴다.

### 꺾기가 성립하려면 — 네 가지 조건 (전부 실측으로 하나씩 드러났다)

1. **그 조각에 목표 박스만 있어야 한다.** 조각 전체가 옆으로 흐르므로 뒤차도 같이 밀린다.
2. **박스가 본선 띠(Y ±500) 안에 있어야 한다.** 씬에는 순환 루프
   (`ConveyorTrack_04/05/06`, Y −6109~−4139)가 있어 분기점을 지나친 박스가 돌아온다.
   X 만 보면 루프 위 박스에게 "꺾어라" 를 내는데 그 박스는 이 조각에 없다.
   **대기 판정(1번)에도 같은 띠를 적용해야 한다** — 안 그러면 루프에 박스가 하나라도
   있는 한 영원히 안 꺾는다.
3. **`main` 이 돌고 있어야 한다.** 꺾기는 방향만 바꾼다. 계량 운전이 `main` 을 세워
   두면 방향만 바뀐 채 그대로 선다. → 꺾는 동안 계량을 잡아 둔다(`_S["diverting"]`).
4. **박스가 지선 폭 안에 완전히 들어와야 한다.** 가장 큰 5호가 480 mm 라 경계에서
   바로 꺾으면 몸통 일부가 레일 밑으로 들어가 걸린다 (양쪽 250 mm 물림).

### 분기점 지오메트리

- **브리지 판** `/World/Bridge_A|B|C` — 본선 롤러 끝(Y 773)과 지선 시작(878) 사이 105 mm.
  Y 713~938 · 상면 **0.7975** (롤러면보다 **2.5 mm 낮게**).
  ⚠ 롤러면과 **같은 높이로 두면 안 된다.** 박스 밑면도 800 이라 앞모서리가 판 측면에
  정확히 걸린다 (실측: Y 0.557 에서 45 s 정지).
- **레일** `/World/Rail_{A,B,C}_{far,near0,near1}` — Y ±790, z 800~950.
  지선 쪽은 분기점 ± 300 mm 를 **비워 둔다.**

## 5. 검증한 것 / 안 한 것

### 배치 (Isaac BBoxCache, 전 항목 통과)
```

```

```
꺾기 -> 지선 진입까지 약 2 초 (Y -0.07 -> 1.24)

RESULT: 통과
```

### 아직 안 한 것
- **픽업 카메라 인식** (`PL_CAM=1`). 프림 경로는 존별로 잡아 뒀지만
  (`cameras.pick_prim`) 픽셀→mm 환산이 test1-1 의 +X 기준이다. 실측 필요.
- **3 대 동시 운전.** 지금은 한 번에 한 존이다. `Cycle` ×3 · 존별 픽업 감지 ·
  소켓 프로토콜에 존 필드가 필요하다.
- **액추에이터**(`Pusher_A/B/C`) — 표식만 있고 충돌체가 없다. 계획에서 제외 상태.
- **턴테이블** — 코너 회전. 넣으면 적재함이 2800 으로 돌아온다.
