# 배송 경로 — 팀원용 사용법

> 팔레트에 쌓인 박스를 **꺼내기 쉬운 순서**로 배송하고, 그 순서의 **실제 도로거리**를
> 네이버 지도 API 로 재는 기능이다. 트랙 D (민범진).

---

## 0. 세 줄 요약

```bash
# ① API 키 없이 — 팔레트에서 꺼낼 순서만 보기
python3 scripts/pallet_access.py --zone B

# ② API 키 넣고 — 실제 도로거리까지 재기
export NCP_API_KEY_ID=발급받은_Client_ID
export NCP_API_KEY=발급받은_Client_Secret
python3 scripts/plan_route.py --zone B
```

**`pallet_access.py` 는 키가 필요 없다.** 키 없이 먼저 돌려 보면 된다.

---

## 1. 왜 이런 게 있나 — 아이디어

박스를 팔레트에 쌓는 건 알고리즘이 알아서 한다. **문제는 그 다음이다.**

트럭 옆문은 팔레트의 **짧은 변** 쪽에 있다. 문에서 먼 안쪽, 그리고 아래에 깔린
박스를 먼저 배송하려면 **위에 있는 박스를 들어내야** 한다. 그게 시간 낭비다.

그래서 순서를 뒤집는다:

```
쌓기   : 알고리즘 마음대로 (충전율 최적화)
배송   : 다 쌓인 팔레트를 보고 → 꺼내기 쉬운 것부터
```

실측 예 (구역 B, 박스 12 개):

```
★ 들어냈다 다시 쌓는 횟수
    접근성 순서로 배송        0 회
    delivery_seq 순서로 배송   5 회
    -> 5 회 절감
```

같은 짐인데 **박스를 5 번 덜 들었다.**

---

## 2. 두 스크립트가 하는 일

### `scripts/pallet_access.py` — API 키 불필요

DB 의 **실측 적재 위치**만 읽어서 계산한다.

```bash
python3 scripts/pallet_access.py --zone B
```

```
  층 순번 박스ID        높이    주소
  10  2  BOX004     281mm  서울 구로구 개봉동 신개봉삼환아파트
  11  2  BOX000     211mm  서울 구로구 고척동 고척파크푸르지오
  ...

★ 들어냈다 다시 쌓는 횟수
    접근성 순서로 배송        0 회
    delivery_seq 순서로 배송   5 회
```

**"어느 박스가 어느 박스 위에 있나"** 를 실제 좌표로 판정한다 —
발자국이 100mm² 이상 겹치고 z 가 분리돼 있으면 "위에 있다" 로 본다.

### `scripts/plan_route.py` — API 키 필요

위 결과를 받아 **실제 도로거리**로 최종 순서를 고른다.

```bash
python3 scripts/plan_route.py --zone B
```

3 단계로 돈다:

| 단계 | API 호출 |
|---|---|
| ① 꺼내기 쉬운 순서 계산 | **0 회** |
| ② 들어내기 최소인 후보만 남김 | **0 회** |
| ③ 남은 후보를 도로거리로 재기 | 후보 수만큼 |

★ **순서는 우리가 정한다.** 네이버는 "이 순서로 가면 몇 km 인가" 만 답한다.
경로 최적화를 네이버에 맡기지 않는다 — 그러면 들어내기 횟수를 무시해 버린다.

## 3. API 키 발급 — 각자 한 번

키는 **저장소에 없다.** 커밋하면 GitHub 이 자동 탐지해 즉시 무효화하고,
지워도 git 히스토리에 영원히 남는다. 각자 발급받아 환경변수로 넣는다.

### 발급 절차

1. [네이버 클라우드 플랫폼](https://www.ncloud.com) 가입 (신용카드 등록 필요, **무료 한도 있음**)
2. 콘솔 → **AI·NAVER API** → **Application** → `Application 등록`
3. **Maps** 항목에서 **Directions 15** 체크
   - ⚠ `Directions 5` 가 아니라 **15** 다. 5 는 경유지가 5 곳까지고 우리는 그 이상 쓴다
4. 등록하면 나오는 **Client ID** 와 **Client Secret** 을 복사

### 환경변수에 넣기

```bash
export NCP_API_KEY_ID=여기에_Client_ID
export NCP_API_KEY=여기에_Client_Secret
```

매번 치기 귀찮으면 `~/.bashrc` 맨 아래에 넣는다:

```bash
echo 'export NCP_API_KEY_ID=여기에_Client_ID' >> ~/.bashrc
echo 'export NCP_API_KEY=여기에_Client_Secret' >> ~/.bashrc
source ~/.bashrc
```

> ⚠ **`.bashrc` 는 저장소 밖이라 안전하다.** 저장소 안에 `.env` 같은 파일을
> 만들지 말 것 — 실수로 커밋된다.

### 키가 없으면

`plan_route.py` 가 이렇게 알려준다:

```
NCP_API_KEY_ID / NCP_API_KEY 환경변수가 없다.
  export NCP_API_KEY_ID=...
  export NCP_API_KEY=...
```

키가 없어도 **`pallet_access.py` 는 그대로 돈다.** 배송 순서까지는 볼 수 있고
도로거리만 못 잰다.

## 4. 미리 돌려 볼 순서

DB 에 적재 기록이 있어야 한다. 없으면 먼저 만든다:

```bash
# ① 정답지(운송장번호 + 주소) 깔기
ros2 run packing_db gen_master_db

# ② ROS 그래프 띄우기
ros2 launch packing_bringup bringup.launch.py

# ③ (다른 터미널) 박스를 흘려보내 적재 기록 만들기
python3 scripts/verify_ros_graph.py

# ④ 결과 보기
python3 scripts/pallet_access.py --zone B
python3 scripts/plan_route.py --zone B      # 키 필요
```

DB 안이 궁금하면:

```bash
python3 scripts/db_peek.py                  # SQL 몰라도 읽을 수 있다
```

## 5. 배송지는 어디인가

`src/packing_db/packing_db/delivery_points.py` 에 **서울 구로구 실제 아파트
15 곳** 이 들어 있다 (구역당 5 곳). 물류센터는 **구로구청**이다.

```
DEPOT = ("서울 구로구 구로동 구로구청", 37.495441, 126.887323)
```

구역 배정은 **주소의 동(洞)** 으로 한다:

| 구역 | 담당 동 |
|---|---|
| A | 신도림동 · 구로동 · 가리봉동 |
| B | 고척동 · 개봉동 |
| C | 오류동 · 궁동 · 온수동 · 천왕동 · 항동 |

박스의 QR 에는 **운송장번호(`BOX001`~`BOX150`)만** 들어 있다.
번호 → 주소 → 동 → 구역 순으로 DB 가 풀어 준다.

### 왜 아파트를 5 곳으로 맞췄나

배송 순서 후보가 `5! = 120` 가지라 **전부 도로거리로 재 볼 수 있다.**
6 곳이면 720 가지가 되어 API 호출이 감당이 안 된다.

---

## 6. 무료 한도와 비용

Directions 15 는 무료 한도가 넉넉하다. 우리 사용량은:

| | 호출 수 |
|---|---|
| `plan_route.py` 1 회 | 후보 수만큼 (보통 수 회 ~ 수십 회) |
| 상한 | `MAX_ROAD_CANDIDATES = 120` 으로 막아 둠 |

**들어내기 최소인 후보만 남기고 재기 때문에** 120 을 다 쓰는 일은 거의 없다.
발표 리허설을 여러 번 돌려도 무료 한도 안에서 끝난다.

---

## 7. 자주 나오는 문제

| 증상 | 원인 |
|---|---|
| `NCP_API_KEY_ID / NCP_API_KEY 환경변수가 없다` | `export` 를 안 했거나 다른 터미널에서 함 |
| `HTTP 401` | 키가 틀렸다. Client **Secret** 을 넣었는지 확인 |
| `HTTP 400` | 경유지가 15 개를 넘었다 (`MAX_WAYPOINTS = 15`) |
| `DB 가 없다: .../palletris.db` | 먼저 `verify_ros_graph.py` 로 적재 기록을 만들 것 |
| 배송지가 하나도 안 나온다 | 그 구역에 `PLACED` 된 박스가 없다. `--zone` 을 바꿔 볼 것 |
| 소요시간이 이상하게 크다 | 네이버 응답의 `duration` 은 **밀리초**다. 초로 착각하지 말 것 |

## 8. 코드 위치

| 파일 | 무엇 |
|---|---|
| `src/packing_db/packing_db/accessibility.py` | 접근성 계산 — 어느 박스가 위에 있나, 꺼낼 순서 |
| `src/packing_db/packing_db/route.py` | 네이버 Directions 15 호출 |
| `src/packing_db/packing_db/delivery_points.py` | 아파트 15 곳 + 물류센터 좌표 |
| `scripts/pallet_access.py` | 접근성만 보기 (키 불필요) |
| `scripts/plan_route.py` | 접근성 + 도로거리 (키 필요) |

`accessibility.py` 와 `route.py` 는 **ROS 의존성이 0** 이다.
`python3` 만 있으면 단독으로 돌릴 수 있다.
