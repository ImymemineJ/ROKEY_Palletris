> 2026-08-27 새벽 작성 (김병직 · Claude). 강사 라이브 시연용.
> 전제: 밤샘 작업으로 **Isaac 안팎 통신이 전부 ROS 2** 가 됐다 (소켓 0개).

## 1. 배치 한눈에 (3대)

| PC | GPU | 역할 | 올라가는 것 |
|---|---|---|---|
| **PC1** | RTX 5080 | **시뮬레이션** | Isaac Sim (씬·물리·로봇 3대) + 카메라 5대 발행 + `/clock`·`/tf` + 로봇 어댑터(Isaac 내장) |
| **PC2** | RTX 5080 | **인식 (AI 비전)** | `vision_node`(cam1 등록·cam2 검증) + 존 인식 3프로세스 |
| **PC3** | RTX 5060 | **관제·계획·기록** | 관제탑(orchestrator) + 적재 알고리즘(algo) + DB(db_service) + 모니터링(`live_view`) |

### 왜 이렇게 나눴나 (발표 멘트)

- **PC1 = GPU 렌더 독점.** Isaac 은 RTX 렌더(프레임당 30~60ms 실측)와 PhysX 가
  GPU·CPU 를 가장 많이 먹는다. 카메라 5대의 렌더 프로덕트도 여기서 그려지므로
  같은 GPU 에 두는 게 맞다 (이미지를 만드는 쪽과 그리는 쪽을 분리하면 손해만 있다).
- **PC2 = 추론 격리.** 이미지 인식은 파이썬 GIL 때문에 한 프로세스에 못 몰아넣어
  구역마다 프로세스를 나눈다 (launch 가 그렇게 설계돼 있다). 시뮬과 다른 PC 에
  둬서 **추론 부하가 물리 프레임을 못 건드리게** 격리한다.
- **PC3 = 가벼운 제어 평면.** 관제탑은 상태머신(이벤트 처리뿐), algo 는 plan 1회
  150~800ms CPU, DB 는 SQLite 단일 writer — GPU 가 필요 없어 5060 으로 충분하다.
  **로봇 명령의 유일한 발신자(관제탑)가 시뮬과 물리적으로 다른 PC** 라는 것이
  "다중 로봇 조율을 네트워크 너머에서 한다"는 시연 포인트다.

## 2. PC별 실행 명령

공통 (3대 모두, 터미널마다):

```bash
export ROS_DOMAIN_ID=115
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export ROS_AUTOMATIC_DISCOVERY_RANGE=SUBNET   # ★ 솔로 테스트의 LOCALHOST 를 빼야 한다!
```

### PC1 — Isaac

```bash
cd ~/palletris_ws && python3 scripts/kill_ros_nodes.py
PL_CAMROS=2 PL_RENDER_EVERY=3 PL_METER=2 PL_SPAWN=8 ./scripts/run_test3_ros.sh
```

- `PL_RENDER_EVERY=3`: 시연은 화면이 주인공이라 **배속(10)보다 부드러움(3)** 을
  택한다. 3이면 약 0.75배속·20fps — 로봇 동작이 자연스럽게 보인다.
  빨리 감고 싶은 구간(적재 후반)에서만 10으로 재시작하는 것도 방법.
- 런처가 알아서 켜는 것: `PL_DROP_KG=3.5`(협곡 낙하) · `PL_CLOCKTF=2`(/clock·/tf).

### PC2 — 인식

```bash
cd ~/palletris_ws && source install/setup.bash
export PL_CONFIG_OVERLAY=src/packing_bringup/config/test_3.yaml
ros2 launch packing_bringup bringup.launch.py \
    vision:=true vision_zone:=false \
    algo:=false db:=false orchestrator:=false \
    2>&1 | tee ~/palletris_logs/vision_$(date +%Y%m%d_%H%M%S).log
```

- `vision_zone:=false` — 픽업 QR 해상도 문제(실측 판독 3/202)로 존 좌표는
  Isaac 실측 대역(PL_GTPICK, PC1)이 낸다. **등록·분류·검증은 진짜 비전.**
- launch 인자 확인 완료 (2026-08-27): `algo`·`db`·`vision`·`vision_zone`·
  `orchestrator` 전부 선언돼 있다 — 위 명령 그대로 동작한다.

### PC3 — 관제·계획·기록

```bash
cd ~/palletris_ws && source install/setup.bash
export PL_CONFIG_OVERLAY=src/packing_bringup/config/test_3.yaml
```

## 2-1. ★ 팔레트 상차 연출 (`PL_OUTFEED=1`)

만재 팔레트가 **셀 컨베이어 -> 커브 -> 팔레트 레인 -> 트럭**까지 가는 모습.
**PC1(Isaac) 실행줄에 `PL_OUTFEED=1` 을 넣어야 켜진다.** 기본은 꺼져 있고,
꺼져 있으면 판갈이 때 박스가 **제자리에서 한 프레임에 사라진다** (사양 §7 의
"트럭 상차" 가 화면에 안 남는다).

```bash
PL_OUTFEED=1 PL_CAMROS=2 PL_RENDER_EVERY=3 PL_METER=2 PL_SPAWN=8 ./scripts/run_test3_ros.sh
```

- 원본은 **김학민 `ship_pallet()`** (`scripts/demo_stack15_test1_1.py`, `0610a00`·`e8a6c84`).
  그쪽은 소켓 하네스 전용이라 ROS 통합 경로에 안 붙어 있었고, 같은 동작을
  `spawner.py` 안으로 옮긴 것이다 (`e33c03f`~`e01ccd3`).
- 걸리는 시간 (기본 1.0 m/s): **A 10초 · B 17초 · C 24초**. 느리게: `PL_OUTFEED_MPS=0.5`
  (김학민 정본, 실물 팔레트 컨베이어 속도). 트럭에 머무는 시간: `PL_OUTFEED_HOLD_S`.
- 반출이 끝나면 **실린 팔레트는 트럭에 남고**, 로봇 옆에 빈 팔레트가 원래 방향으로 놓인다.
- 로그로 단계 확인: `커브 진입` -> `커브 통과 (90도) · 레인 정렬 ±N mm` ->
  `트럭 적재 완료` -> `트럭에 팔레트를 남기고 빈 판을 놓았다`.
- ⚠ **레인 정렬 값을 볼 것.** 돌고 난 팔레트 폭 0.80 에 레인 간격 0.83 —
  **편도 여유 15 mm** 다. 이 보정이 없으면 가이드를 문다.
- 만재를 기다리지 않고 시험만 하려면 (씬만 비우고 heightmap 은 안 건드린다):
  `ros2 service call /sim/swap_pallet packing_msgs/srv/SwapPallet "{zone: 'B'}"`

## 3. 리소스 효율 — 발표에서 짚을 것 (전부 실측 근거)

| 장치 | 무엇 | 근거 숫자 |
|---|---|---|
| 렌더 스킵 (`PL_RENDER_EVERY`) | 병목이 물리(2.6ms)가 아니라 렌더(30~60ms)임을 **계측으로 확인**하고 렌더만 건너뜀 | 계측 전 0.7배속 → 2.3배속 |
| 추론 주기 제한 | 천장 카메라는 **도착 신호가 왔을 때만** 추론 (§13 평가항목 "처리 효율") | 설계 반영 |
| 카메라 QoS | `BEST_EFFORT` — RELIABLE 이면 이미지가 아예 안 옴 | §3-4 규약 5 |
| 서비스 비동기 | 전 노드 `call_async` + 콜백 — 대기 중 CPU 0 | §9 규약 |
| GIL 분리 | 인식은 구역별 **프로세스** 분리, 관제탑은 이벤트 기반 **1프로세스** | launch 설계 |
| 계산 예산 재배치 | plan 2.7ms→앞보기 k4 로 300~800ms 씀 — 로봇 모션 5~10초 대비 예산 1000배 여유를 활용 | §10-2 사상 |

## 4. 다중 PC 네트워크 준비물 (시연 전날 체크)

> ★★ **git 에 안 오는 생성물 3종** (2026-08-27 강의실 실측 — 셋 다 실제로 밟았다):
> 1. **씬 USD** (`~/isaac_scenes/Collected_test_3/`, 1.2GB) — PC1 만 필요.
>    낡으면 "Selected Prim is not a Rigid Body" 전면 + 로봇 아티큘레이션 없음.
>    배포: `SCENE_HOSTS="rokey@10.10.0.2" ./scripts/sync_scene.sh` (또는 받는 쪽에서
>    `rsync -av --delete --exclude='_archive/' byeongjik@10.10.0.3:isaac_scenes/ ~/isaac_scenes/`)
> 2. **`qr_labels/`** — PC1(Isaac) 필요. 없으면 박스에 QR 이 안 붙어 인식 전멸.
> 3. **`palletris.db`** — PC3(DB) 필요. 없으면 등록 실패("DB 에 없음 -> 폐기").
>    ⚠ 2·3 은 **짝이다** (라벨은 마스터 DB 에서 구움) — 같은 원본에서 함께 복사할 것.

1. **`ROS_AUTOMATIC_DISCOVERY_RANGE=SUBNET`** — 밤샘 솔로 테스트는 전부
   `LOCALHOST` 였다. 이대로 가져가면 서로 안 보인다. ★ 1순위 함정.
2. **DDS 버퍼** — 이미지(1280×720×5대)가 UDP 단편 손실을 낸다. §15 실측:
   기본 버퍼 깊이 커버리지 4/8 → 송수신 16MB 로 6/8.
   `FASTRTPS_DEFAULT_PROFILES_FILE` + `sudo sysctl net.core.rmem_max=16777216`.
3. **같은 브랜치·같은 빌드** — `packing_msgs` 는 전원 재빌드 필수 (§14).
4. **`use_sim_time`** — PC2·PC3 노드 전부 true, PC1 이 `/clock` 을 낸다
   (PL_CLOCKTF=2 로 보장, 발행자 1 확인: `ros2 topic info /clock`).
5. **시계 동기(선택)** — sim time 을 쓰므로 필수는 아니나 로그 대조가 편해진다.

### 이미지 대역폭 주의

1280×720 rgb8 5대를 풀레이트로 흘리면 이론상 100MB/s 급이다. 실제로는 렌더
스킵 때문에 프레임이 그보다 훨씬 적게 나가지만, **시연장 유선 공유기**를 쓰고
무선은 피할 것. 끊기면 인식 커버리지가 조용히 떨어진다 (에러 안 남).

## 6. 시연 흐름 제안 (숫자는 오늘 밤 실측)

1. 스폰 → cam1 이 **색·크기로 등록** ("BOX001 4호 → zone B 동 개봉동" 로그 화면)

3. 로봇 3대 동시 사이클 — 대기 자세(스토퍼 상공 선점), 협곡 낙하 배치

5. 종료 지표: 존별 적재 21~29개 · 적재율 62~75% (평균 66%, 문헌 BPP-1 66.9% 와 동급)
