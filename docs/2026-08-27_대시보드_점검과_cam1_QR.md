## 2. 좌우 반전 — 3D 그림이 거울에 비친 모습이었다

김병직님이 "Isaac 과 좌우가 반대인 것 같다" 고 지적해 찾았다. **맞았다.**

등각 투영의 네 요소 중 **가로축만** 반대 부호였다:

| 그림의 요소 | 뜻하는 카메라 위치 |
|---|---|
| 그리는 면 (`x=x1`·`y=y1` → +X면·+Y면) | +X, +Y 쪽 |
| 그리는 순서 (`x+y+z` 작은 것부터 = 먼 것 먼저) | +X, +Y 쪽 |
| 세로축 (`x+y` 클수록 아래, `z` 클수록 위) | +X, +Y, +Z |
| **가로축 (`x-y` → +X 가 오른쪽)** | **−X, −Y 쪽 ← 여기만 반대** |

즉 **어떤 시점에서도 성립하지 않는 그림**이었다. 수치로도 확인했다 —
카메라를 (+X,+Y,+Z) 에 두면 화면 오른쪽 방향은 `[-0.707, +0.707, 0]` 인데
코드는 `[+1, -1, 0]` 을 쓰고 있었다. 정확히 부호 반대다.

**축정렬 직육면체 더미는 거울에 비춰도 그럴듯해 보인다.** 그림만 봐서는 안 드러나고
Isaac 화면과 나란히 놓아야 보인다 — CLAUDE.md §10-3 이 말하는 그 상황이다.

### 2-1. 높이 지도도 같은 병이었다

SVG 는 아래가 +y 라 월드 +Y 를 그대로 내려 그리면 역시 좌우가 뒤집힌다.
(위에서 내려다본 그림에서 +X 가 오른쪽이면 +Y 는 위쪽이어야 한다.)

3D 만 고쳤으면 두 탭이 서로 반대로 보였을 것이다. 같이 고치고, **두 그림을 같은
방향에서 보도록** 맞췄다.

### 2-2. 방향 표시를 넣었다

로봇이 선 자리를 두 그림에 점으로 찍는다. Isaac 화면에서 로봇이 있는 쪽과
비교하면 3초 만에 맞는지 알 수 있다.

★ **로봇 위치는 설정에서 읽는다.** 값을 박으면 한쪽이 반드시 틀리기 때문이다:

| 설정 | 팔레트 | 로봇 (팔레트 기준) |
|---|---|---|
| `system.yaml` 정본 | 1200×800 | (600, **−500**) → **−Y 쪽** |
| `test_3.yaml` 오버레이 | 800×1200 | (**1300**, 600) → **+X 쪽** |

## 3. 연결 배지가 거짓말을 하고 있었다

백엔드가 죽었는데 "관제탑 실시간 연결" 이 초록으로 남아 있었다.

원인: API 를 `/api/state` 하나로 합치면서(`35c5748`) `pollLive` 함수가 지워졌는데
**부르는 줄만 남아 있었다.** 브라우저 콘솔에 `ReferenceError: pollLive is not defined`.

결과가 둘이었다.

1. 백엔드가 끊겨도 배지를 빨강으로 바꿔줄 사람이 없다
2. 그 줄 뒤의 `setInterval(renderFresh, 1000)` 이 아예 등록되지 않는다

`refresh()` 의 실패 경로에서 배지를 끄도록 고쳤다.

## 4. 설명 말풍선 (61곳)

지표·카드·탭에 마우스를 올리면 그 숫자가 무슨 뜻인지 뜬다. **분모까지 적는다** —
"cam1 이 읽은 96개 ÷ 라인에 올라온 132개(읽은 것 + 놓친 것 36개)".

- **CSS 만으로 그린다.** 스크립트가 죽어도 뜨고, 설명이 마크업 옆에 붙어 있어
  화면과 설명이 갈라지지 않는다
- **스크롤 목록 안(`.unload`)은 브라우저 기본 툴팁**을 쓴다. 말풍선은 그냥 자식
  요소라 조상의 `overflow` 에 잘린다 — 그 안에서는 아예 안 보인다

지표 다섯 칸은 **색을 뺐다.** 두 칸만 빨강·초록이라 나머지와 다른 물건처럼 보였다.
기준값(95% 위 / 70% 아래)은 말풍선이 알려준다.

## 5. cam1 실시간 영상 (꺼낼 순서 탭 자리)

```
Isaac(cam1) ──/cam1/rgb──> 백엔드(server.py) ──PNG──> 브라우저 <img>
              sensor_msgs/Image                 4 Hz
```

**브라우저는 ROS 를 모른다.** 백엔드가 구독해 그림으로 바꿔 주고 화면은 `<img>` 만
갈아 끼운다. rosbridge 도, Pillow·OpenCV 도 안 쓴다 — PNG 는 zlib 한 번이면 되므로
표준 라이브러리만으로 짰다.

- 구독 QoS 는 **BEST_EFFORT**. 기본 RELIABLE 이면 이미지가 하나도 안 온다 (§3-4 규약 5)
- 640 px 로 줄여 보낸다. 한 장 **160 KB · 인코딩 8 ms**
- ★ **아무도 안 볼 때는 프레임을 붙잡지도 않는다.** 1280×720 한 장이 2.7 MB 라
  30 Hz 로 복사하면 초당 80 MB 다. 실측: 12초 안 보면 프레임이 8.2초까지 늙고,
  요청하면 0.09초로 돌아온다
- 영상이 3초 넘게 안 바뀌면 "카메라가 멎었다". 단 **두 번 연속일 때만** — 탭을
  다시 열 때 오는 마지막 프레임을 고장으로 읽으면 멀쩡한데 경고가 번쩍인다
- 영상이 없으면 이유를 그대로 띄운다 (`ROS 구독이 꺼져 있다` / `아직 한 장도 안 왔다`)

**꺼낼 순서는 지우지 않았다.** 데이터(`/api/state` 의 `unload`)와 그리는 함수를 그대로
뒀고, 되살리는 방법은 `renderUnload` 주석에 적었다 — 서버는 손댈 것이 없다.

## 6. QR 표시

QR 을 **구역 색**으로 두르고 `BOX008 · A구역` 을 띄운다.

### 6-1. 색은 씬이 쓰는 색 그대로

**A 빨강 · B 초록 · C 파랑.** `routing.by_color` + `boxes.colors` 를 이어 붙여
유도한다 (`#e60808` · `#08b214` · `#081ae6`). test_3.yaml 이 같은 이유로 네 번째
표를 금지하고 있다 — 화면 색이 씬과 다르면 "저 빨간 박스" 가 두 가지를 가리킨다.

### 6-2. 왜 인식 노드에서 안 받나

`vision_node` 는 QR **문자열만** 쓰고 위치는 버린다 (`detect.read_qr`). 위치를
받으려면 `packing_msgs` 에 필드를 늘려야 하고 그건 **전원 재빌드**다 (§11·§14).
화면에 표시하자고 공용 인터페이스를 바꿀 일은 아니라, 보여주는 쪽에서 한 번 더 읽는다.

⚠ 그래서 이 표시는 **"대시보드가 읽은 것"이지 "인식 노드가 등록한 것"이 아니다.**
둘이 다르면 그 자체가 인식 쪽 단서가 된다.

### 6-3. 세 번 걸렸고 세 번 고쳤다 (전부 실측)

| 증상 | 원인 | 고친 방법 |
|---|---|---|
| 작은 QR 을 못 읽는다 | 속도 때문에 640 으로 줄여서만 훑었다. **160 px 아래는 못 읽는다** | 못 읽었을 때만 원본 해상도로 한 번 더 (50 px 까지 성공 · 40 px 은 한계) |
| 그랬더니 **CPU 92 %** | QR 이 없는 화면에서도 매번 두 번 훑는다 | 훑는 간격 제한(0.4초) + 전체 훑기 제한 → **14 %** |
| 박스가 QR 을 **뒤따라간다** | 전체 훑기가 비싸 0.4초에 한 번인데 벨트는 0.5 m/s | 직전에 찾은 자리 둘레만 먼저 본다(몇 ms) → **48/48 프레임 · 오차 0 px** |
| QR 3개 중 **1개만** 표시 | ROI 추적이 처음 잡은 것만 본다 — 라인에서는 **두 번째 박스부터 안 뜬다** | 0.7초마다 화면 전체를 다시 훑는다 |

### 6-4. 브라우저 함정 둘 (같은 실수 반복 금지)

- **SVG 는 `el.hidden = false` 가 안 먹는다.** `hidden` 은 HTMLElement 의
  프로퍼티라 SVG 요소에 대입하면 자바스크립트 변수만 생기고 속성은 그대로 남는다.
  내용은 다 그려 놓고 화면에는 아무것도 안 보였다 → `removeAttribute` 로 바꿨다
- **SVG 의 `fill`/`stroke` 는 CSS 보다 순위가 낮다.** '표현 속성' 이라 어떤 CSS
  규칙에도 진다. 색을 인라인으로 넣었는데 전부 회색으로 나왔다 → CSS 에서 색을
  빼고 모양(굵기·모서리)만 남겼다

## 7. `start_demo.sh` — DB 를 비우고 시작한다

Isaac 은 껐다 켜면 씬이 비는데 `palletris.db` 는 안 비워진다. 그래서 대시보드가
**어제 실행을 오늘 것처럼** 보여준다.

지표가 "시간이 뒤로 간 자리" 로 실행을 가르기는 하지만, 그 뒤에 기록이 30건은
쌓여야 인정한다 (`metrics.RUN_MIN_EVENTS`). **시작 직후 한동안은 반드시 어긋난다.**
Isaac 을 Stop 안 하고 이어 돌리면 시간 점프가 없어 아예 못 가른다.

```bash
./scripts/start_demo.sh           # 남은 노드 정리 → 백업 → 초기화 → Isaac
./scripts/start_demo.sh --keep    # 안 비우고 실행
```

- ★ **지우기 전에 항상 백업한다** (`~/palletris_runs/`). 되돌릴 수 없고, 발표 직후
  "방금 그 실행" 을 다시 봐야 할 일이 실제로 생긴다
- ★ 남은 노드를 먼저 정리한다. `db_service_node` 가 DB 를 잡고 있으면
  `database is locked` 가 난다 (§10 유일 writer 규약)
- ⚠ **껍데기다.** 실행은 `run_test3_ros.sh`(트랙 B) 가 그대로 하고 그 파일은
  한 글자도 안 고쳤다 — 인자·환경변수는 전부 넘어간다

### 7-1. 검토했지만 안 쓴 대안 둘

| 안 | 왜 안 썼나 |
|---|---|
| 실행마다 DB 파일을 따로 (`PALLETRIS_DB`) | 기록이 남는 건 좋지만 모든 터미널에 같은 값을 넣어야 한다. 백업으로 같은 효과 |
| DB 에 `pallet_seq`·실행 번호 컬럼 추가 | **근본 해결이지만 스키마 변경 = 전원 재빌드.** 발표 전에 하기엔 크다. 팀 안건으로 남긴다 |

## 8. 실행 방법

```bash
# 터미널 1 — Isaac (DB 를 비우고 시작)
cd ~/palletris_ws && ./scripts/start_demo.sh

# 터미널 2 — 대시보드
cd ~/palletris_ws && source install/setup.bash
export PL_CONFIG_OVERLAY=$PWD/src/packing_bringup/config/test_3.yaml
python3 scripts/dashboard/server.py --port 8090
```

브라우저 http://127.0.0.1:8090

**카메라가 붙었는지는 서버 뜰 때 이 줄로 안다:**

```
카메라  : /cam1 → cam1(1280x720)      ← 붙음
카메라  : /cam1 → 아직 프레임 없음      ← Isaac 이 안 떴다
```

- `PL_CAMROS` 는 **안 써도 된다** (기본 1 = 우리 코드가 쏜다). `2` 는 씬에 중복으로
  들어있는 카메라 그래프 7개를 꺼서 렌더를 아끼는 값이다 — 화질·속도 옵션이지
  카메라를 켜는 스위치가 아니다
- 다른 PC 에서 볼 때만 `--host 0.0.0.0`
- 다른 카메라: `--cam /cam1,/cam2,/pick_cam_a` + `truck.js` 의 `CAM_NAME`
